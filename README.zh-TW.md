# Skilvella

[日本語](README.ja.md) | [English](README.md) | [简体中文](README.zh-CN.md) | **繁體中文** | [한국어](README.ko.md) | [Español](README.es.md) | [Français](README.fr.md) | [Deutsch](README.de.md) | [Português (Brasil)](README.pt-BR.md)

這是一款本機應用程式，可在瀏覽器中整理大量 `SKILL.md` 檔案，並透過 MCP 只載入你需要的技能。無論你有多少技能，它都只會公開三個 MCP 工具。

- 可依名稱、說明、內容與標籤進行關鍵字搜尋，包含日文子字串比對。
- 支援資料夾註冊、技能建立、內容編輯、標籤與分類、批次操作，以及逐一技能切換 MCP 公開狀態。
- 每次編輯前都會儲存歷史紀錄並可還原，可偵測與外部編輯之間的衝突，並檢查重複名稱、語法錯誤與遺失的檔案。
- 支援 Windows / macOS / Linux。請在同一台電腦上使用瀏覽器。

## 開始使用

在 Windows 上，請執行 [SkilvellaApp-win-Setup.exe](https://skilvella.kagayoi.com/SkilvellaApp-win-Setup.exe)，然後從開始功能表啟動「Skilvella」。安裝程式（Setup）版會在安裝時自行註冊，於目前使用者登入時自動啟動。從既有的獨立版（ZIP）切換時，請先從工作列通知區域的圖示結束舊版（若舊版仍在執行，預設連接埠（7465）將無法使用，安裝程式（Setup）版會顯示相關訊息且不會啟動）。ZIP 版的登入自動啟動註冊，會在安裝時自動切換為安裝程式（Setup）版，開始功能表中的「Skilvella」捷徑也會隨之指向安裝程式（Setup）版。如果你原本已停用自動啟動，則會維持停用。解除安裝時，也會一併移除指向安裝程式（Setup）版的自動啟動註冊。舊版的資料夾不會自動刪除，若不再需要，請自行移除。如果你使用的是沒有自動更新機制的舊版安裝程式（Setup）版（1.1.4 至 1.1.6），請使用新的 Setup 重新安裝一次。標準資料資料夾 `%LOCALAPPDATA%\Skilvella` 為共用，解除安裝後仍會保留。安裝程式版會自動更新（[應用程式更新](#app-updates)）。

若要使用 ZIP 版或 macOS 版，請下載對應的套件（[Windows x64](https://skilvella.kagayoi.com/portable/Skilvella-windows-x86_64.zip) 或 [Mac Apple Silicon](https://skilvella.kagayoi.com/portable/Skilvella-macos-aarch64.tar.gz)，由 skilvella.kagayoi.com 提供）並解壓縮。1.1.8 及更早的 ZIP 版與 macOS 版是透過 GitHub 檢查更新，此方式已不再使用，因此若你正在使用這些版本，請手動重新安裝一次新的套件。

- Windows x64：將 `Skilvella-windows-x86_64.zip` 解壓縮到你要長期使用的資料夾，然後啟動 `skilvella.exe`。它會在工作列通知區域執行，不會開啟終端機，第一次正常啟動時會將「Skilvella」新增到目前使用者的開始功能表。
- Mac Apple Silicon：解壓縮 `Skilvella-macos-aarch64.tar.gz`，並在終端機中執行 `./skilvella`。
- 解壓縮之前，你可以依據 [`SHA256SUMS.txt`](https://skilvella.kagayoi.com/portable/SHA256SUMS.txt) 驗證套件的 SHA-256。

若要在 Linux 上使用或從原始碼建置，請參閱[開發指南](docs/DEVELOPMENT.md)。

Skilvella 在 Windows 上會於工作列通知區域顯示圖示，在 Mac 上則顯示於選單列。按一下滑鼠左鍵，即可在預設瀏覽器中開啟管理介面。按一下滑鼠右鍵（Mac 上為 Control 加按一下），可選擇「開啟管理介面」、「檢查更新」、「重新啟動服務」或「結束」。在 Windows 上，若看不到圖示，也請檢查通知區域的隱藏圖示溢位選單。

「重新啟動服務」會在同一個處理程序與相同的 URL 下重新啟動 HTTP/MCP 伺服器與檔案監看。已儲存的技能與設定都會保留。重新啟動期間的重複請求會被合併，且重新啟動會等待進行中的 HTTP 操作完成。MCP 連線會中斷，請從你的用戶端重新連線。使用已開啟的管理頁面之前，請先重新載入。「結束」會關閉伺服器與圖示。

你也可以直接在 [http://127.0.0.1:7465/](http://127.0.0.1:7465/) 開啟管理介面。MCP 端點為 `http://127.0.0.1:7465/mcp`。在沒有顯示器的環境中，請傳入 `--no-tray`。在 Linux 上不會顯示圖示，而是作為 HTTP/MCP 伺服器執行。

對於 Windows 獨立版的配置，不帶引數啟動時會嘗試註冊為目前使用者登入時自動啟動。如果已經註冊，從其他位置啟動可執行檔並不會變更已註冊的路徑。你可以在 Windows「設定」→「應用程式」→「啟動」中開啟或關閉自動啟動。若本次啟動要略過註冊，請傳入 `--no-autostart`。若為 Toolport 管理下的自動啟動，請在 Toolport 端進行設定。

執行時不需要 Rust、Node.js、Python 或外部資料庫伺服器。從終端機啟動時，也可以在所附加的主控台中以 `Ctrl+C` 結束。

## 管理你的資料庫

首次啟動時，Skilvella 會自動偵測管理資料夾。它會依序檢查既有的 `~/.agents/skills`、`$CODEX_HOME/skills` 與 `~/.codex/skills`，若都找不到，則會在資料資料夾旁建立 `<data-folder-name>-skills`。只包含 Skilvella 所產生的 Codex 呼叫入口的候選位置會被略過，這些入口本身也不會被算作受管理的技能。此規則僅在資料資料夾保有這些入口的所有權紀錄時才成立。如果你重新建立資料資料夾，或以 `--data-dir` 指向其他資料夾，先前產生而仍然留存的入口會被註冊為一般技能。若先前已註冊過來源，則以該設定為優先並沿用。如果因讀取入口所有權紀錄或候選位置時發生問題而無法完成自動偵測，則會保留已儲存的自動註冊目標。請在資料庫左側的資料夾清單中確認偵測狀態。

資料庫是單一畫面：左側是受管理資料夾的清單，右側是技能清單。按下「＋ 新增資料夾」會開啟作業系統的標準資料夾選擇器；所選資料夾會直接註冊並掃描。檔案不會被移動。你不需要輸入名稱，會以資料夾名稱作為顯示名稱（之後可以透過「變更顯示名稱」修改）。在無法開啟對話方塊的環境（例如 SSH 工作階段）中，請在「輸入路徑新增」下輸入絕對路徑。

在左側選取資料夾後，會顯示其位置、數量與標準探索路徑警告，以及「變更顯示名稱」與「停止管理」。對於預設資料夾，可以用「變更參照資料夾」切換所參照的資料夾，並用「瀏覽…」從對話方塊中挑選。此設定在重新啟動後仍會保留，且「停止管理」不會刪除檔案。如果你選擇的資料夾已在管理中，或與受管理的資料夾具有上下層關係，則會停止新增，並顯示發生重疊的資料夾名稱。如果資料夾在 Skilvella 之外被移動或刪除，側邊欄與該資料夾的頁面會顯示警告，並在解決之前停止同步。若是移動了，請開啟「變更資料夾位置」，輸入新位置（或用「瀏覽…」挑選）。僅更新登記的位置，不會移動檔案，並保留技能 ID、公開狀態、用法設定與變更紀錄。若不再需要該資料夾，請選擇「停止管理」。若新位置已作為另一個資料夾受管理，請先停止管理那個資料夾。

透過新增、自動偵測或外部編輯找到的新技能，若可讀取，會以**開啟 MCP 公開**的狀態註冊。發生讀取錯誤或 frontmatter 無效的技能會維持未公開，即使修正後也不會自動公開。既有技能的公開狀態不會因重新掃描或啟動而改變（你設為未公開的技能絕不會自動公開）。在 Windows 與 macOS 上，僅 ASCII 字母大小寫不同的資料夾名稱會被視為同一個技能，其公開狀態不會改變。如果你不想公開某個技能，請在新增資料夾後，於清單的「狀態」欄選擇「未公開」。在清單的「狀態」欄選擇「已公開」或「未公開」會立即儲存。你也可以在個別頁面或使用清單的批次操作來切換。切換為已公開時，會重新檢查檔案，遺失、有讀取錯誤或 frontmatter 無效的技能不會被公開；選取會還原並顯示原因。標籤與分類不會改變。

資料庫從一開始就會列出所有資料夾的技能，並可就地搜尋。直接包含 `.git` 目錄或檔案的資料夾，會作為來源（儲存庫）巢狀顯示在該資料夾之下，其餘則歸入「個人技能」。如果某個資料夾內沒有直接的來源儲存庫，而該資料夾本身就是 Git 儲存庫，則整個資料夾會成為一個來源。一般清單會顯示目前存在的技能。舊的註冊記錄（例如移動之前的記錄）會被保留，可在狀態「找不到」或「全部」以及左側的「清理不存在的技能記錄」下查看。在「找不到」清單中，「批次刪除遺失記錄」會刪除符合搜尋條件的所有頁面中的註冊資料、設定與歷史紀錄。此操作無法復原。它不會變更實際檔案，且若無法連到來源或路徑存在，則會中止所有項目的刪除。分類可以從各技能的中繼資料編輯。

Skilvella 會**不限深度地遞迴**搜尋已註冊資料夾中的 `SKILL.md` 檔案。即使找到技能，它也會繼續掃描更深的子目錄。父技能與子技能以各自獨立的 ID 與公開設定管理，子技能的檔案不會包含在父技能的 MCP 公開範圍內。符號連結、Windows 連接點、`.git`、`node_modules`、`target` 與 `.work` 會被排除。取消註冊資料夾不會刪除原始檔案。如果你重新新增先前已停止管理的資料夾，其先前的管理資料（公開設定、標籤、歷史紀錄）會被還原。同名的資料夾彼此不會衝突。

儲存內容會變更已註冊位置中的實際檔案。預覽會停用 HTML、圖片載入與連結動作，也不會執行指令碼。在外部編輯器中所做的變更會被自動監看。若未反映，請使用「重新掃描」。

出現讀取錯誤時，請從資料庫的「查看並修正讀取錯誤」或左側的「讀取錯誤」開啟跨資料夾的錯誤清單。開啟技能名稱或路徑以確認原因，若為語法錯誤，請修正內容後儲存。如果檔案無法讀取，請檢查其位置、權限與字元編碼，然後重新掃描。錯誤解決後，通知就會消失。

## 應用程式更新

**安裝程式（Setup）版**：預設會開啟自動更新。它會在啟動時，以及持續執行期間每 24 小時檢查一次新版本，若有新版本便下載。更新會在下次啟動時自動套用，並以相同設定重新啟動。距離上次檢查不到 24 小時時不會連線。如果檢查或下載失敗，會繼續執行目前的版本。你可以在「設定」的「應用程式更新」下關閉「啟動時自動更新」（此設定儲存在資料資料夾中的 `app-update.json`，例如 `%LOCALAPPDATA%\Skilvella`，不會變更技能資料庫）。「檢查更新」不受 24 小時間隔限制，會立即檢查；「安裝更新」會下載更新並立即重新啟動。更新資訊是從 `skilvella.kagayoi.com` 取得。

以下適用於獨立版（ZIP）與 Mac。

你可以從「設定」中的更新區段，或從系統匣選單的「檢查更新」，查看 skilvella.kagayoi.com 上最新的穩定版。選擇「安裝更新」會透過 HTTPS 下載適用於 Windows x64 / Mac Apple Silicon 的套件與 `SHA256SUMS.txt`，驗證 SHA-256 後再套用。這需要作業系統內建的 `curl`，以及可執行檔所在位置的寫入權限。Linux 或其他 CPU 不支援應用程式內更新。

更新會等待進行中的 HTTP 操作完成後才結束，然後以相同的啟動引數與工作資料夾重新啟動。請重新連線你的 MCP 用戶端。如果套件驗證失敗，則會保留目前的版本。若套用更新後無法啟動新的處理程序，它會嘗試還原舊的可執行檔或 Toolport 的參照目標。發起更新的設定頁面會在新版本回應後自動重新載入。如果你在應用程式重新啟動之前就已開啟的舊設定頁面上進行更新操作，系統會要求你重新載入頁面。

更新前可執行檔所在的相同位置會建立 `.skilvella-update-*` 資料夾，並保留 `update.log`。在一般配置下，它也會儲存供復原用的 `previous-binary`。此資料夾建立超過 24 小時，且沒有更新正在進行、其中只包含更新程式建立的檔案時，Skilvella 會在啟動時自動刪除。你不需要自行刪除；若要手動刪除，請等更新輔助程式結束後再進行。

在 Toolport 的 `Skilvella-Latest.ps1` 管理下，會保留既有版本，新增新版本的資料夾與驗證資訊，並切換啟動器的參照目標。更新輔助程式會一直執行到重新啟動後的應用程式結束為止，因此請在刪除更新資料夾之前先結束 Skilvella。

當 Skilvella 是由外部處理程序監控工具啟動時，你可能需要從該工具重新啟動它。如果無法取得 Toolport 的啟動鎖定，則不會套用更新。若未啟動，請重新執行啟動器。包含日文等非 ASCII 字元的 Toolport 管理位置不支援應用程式內更新。一般的獨立版配置不受此限制。

## MCP 連線

請將以下 URL 註冊到支援 Streamable HTTP 的用戶端。

```text
http://127.0.0.1:7465/mcp
```

在 Toolport 中，請將其註冊為 HTTP 伺服器並指定相同的 URL。請保持 Skilvella 在執行中。

| 工具 | 用途 |
| --- | --- |
| `search_skills` | 搜尋已公開的技能，並取得摘要與 ID |
| `load_skill` | 指定 ID 以取得 `SKILL.md` 的內容與參考檔案清單 |
| `read_skill_file` | 依行取得技能下的 UTF-8 文字 |

對於 `load_skill`，請持續傳入接續引數直到 `next` 為 null，將內容串接起來，然後遵循其中的指示。清單通常每頁 100 筆，路徑總計最多 8 KiB，但如果單一路徑超過 8 KiB，則該路徑會單獨傳回，因此回應會變大。請一次取得一個技能及其所需的參考檔案。對於參考檔案，請使用 `read_skill_file`，以 `next_text_offset` 取得所需行範圍直到結尾，只有在需要更多行時才使用 `next_start_line`。同一行範圍的位元組分頁會原樣串接，而在串接不同行範圍時會插入換行。使用 `next_text_offset` 接續時，請保持 `start_line` 與 `max_lines` 不變；若要取得下一個行範圍，請將 `start_line` 設為 `next_start_line`，並將 `text_offset` 重設為 0。換行符號會如先前一樣被正規化，且結尾的換行會被移除。接續時，請將傳回的 `revision` 指定為 `expected_revision`。如果檔案在這期間已變更，請從頭重新取得。 `id` 為 `search_skills` 傳回的技能 ID；若與已發布技能的名稱完全相符且唯一，也可使用名稱，名稱有多個相符時會傳回候選 ID。首次呼叫 `read_skill_file` 只需 `id` 與 `path`；結果被截斷時，請直接傳入已包含 `expected_revision` 的 `next` 物件繼續。

MCP 是唯讀的。它無法傳回未公開技能、frontmatter 無效的技能或遺失技能的內容。也沒有執行參考檔案的功能。內容上限為 2 MiB，參考文字上限為 1 MiB。

僅透過 MCP 公開，並不會改變代理程式依標準方式探索並載入相同技能的事實。為避免重複載入，請將技能放在代理程式標準探索路徑之外，並用資料庫的「＋ 新增資料夾」註冊該位置。Skilvella 不會移動檔案。如果需要移動既有檔案，請自行處理，再於該資料夾的「變更資料夾位置」中指定新位置。Codex 的設定檔不會被編輯。變更標準探索路徑後，請重新啟動 Codex。已載入對話中的內容不會被移除。請另外檢查自訂探索設定與其他用戶端。

## 自動選擇與命令候選

請先使用採用 [MCP 連線](#mcp-connection) 的用戶端註冊並驗證 Skilvella。在「設定」的「呼叫入口同步」下，勾選同步目標（Codex、Claude Code、Grok、Cursor、GitHub Copilot、Devin；可複選）並儲存，Skilvella 本身就會自動同步各用戶端的呼叫入口。在這台電腦上找不到設定資料夾（例如 `~/.cursor`）的用戶端，會收合到同一表單中的「其他用戶端」下；已啟用或有同步錯誤的用戶端一律顯示。狀態表只列出已啟用的用戶端與有同步錯誤的用戶端。如果你在舊版中啟用了「Codex 整合」，它會以選取 Codex 的狀態沿用。此功能在 Windows、macOS 與 Linux 上運作方式相同，既不使用工作排程器，也不使用任何獨立的常駐處理程序。同步會在啟動時、管理操作之後以及定期檢查期間執行，並且設定在服務重新啟動後仍會保留。

| 同步目標 | 入口位置 | 公開給探索的方式 | 自動選擇控制 |
| --- | --- | --- | --- |
| Codex | `~/.agents/skills/skilvella/<name>` | 實際檔案（Codex 會搜尋巢狀資料夾） | `agents/openai.yaml` |
| Claude Code | `~/.claude/skilvella/skills/<name>` | 指向 `~/.claude/skills/<name>` 的連結（Windows 上為連接點，macOS 與 Linux 上為符號連結） | `disable-model-invocation`、`user-invocable` |
| Grok | `~/.grok/skills/skilvella/<name>` | 實際檔案（Grok 會搜尋巢狀資料夾） | `disable-model-invocation`、`user-invocable` |
| Cursor | `~/.cursor/skills/skilvella/<name>` | 實際檔案（Cursor 會搜尋巢狀資料夾，但可能不跟隨連結） | `disable-model-invocation` |
| GitHub Copilot | `~/.copilot/skilvella/skills/<name>` | 指向 `~/.copilot/skills/<name>` 的連結 | `disable-model-invocation`、`user-invocable` |
| Devin | `<Devin 設定>/skilvella/skills/<name>` | 指向 `<Devin 設定>/skills/<name>` 的連結 | `triggers: [user]` |

只有在「僅自動選擇」時才會寫入 `user-invocable: false`（技能會從 `/` 選單中消失，但仍可被自動選擇）。Codex、Cursor 與 Devin 無法隱藏命令，因此它們會得到與「自動選擇＋命令候選」相同的入口（Codex：`agents/openai.yaml` 中的 `allow_implicit_invocation: true`）。

`<Devin 設定>` 在 Windows 上為 `%APPDATA%\devin`，在 macOS 與 Linux 上為 `~/.config/devin`（不使用 `XDG_CONFIG_HOME`）。GitHub Copilot 一律使用 `~/.copilot`，不遵循 `COPILOT_HOME`。

Claude Code 只會搜尋 `~/.claude/skills` 正下方的一層，因此入口會放在探索路徑之外，並為每個技能建立一個連結。如果 `~/.claude/skills` 中已有同名的既有技能或連結，則不會覆寫，且該名稱會顯示為同步錯誤。如果你依照舊版指引，手動建立了從 `~/.claude/skills/<name>` 指向 `~/.agents/skills/skilvella/<name>` 的連結，它會被重新指向 Claude Code 入口並接手管理，但僅限於屬於同步目標的名稱。不屬於同步目標的名稱，其連結不會被動到（如果你停用 Codex，它們的參照目標就會消失）。停用 Claude Code 的同步時，只會移除 Skilvella 所建立或接手的連結。如果你已將 `~/.claude/skills` 本身註冊為受管理資料夾，則不會執行同步。

只有 Claude Code 的入口還會沿用原始 `SKILL.md` 的部分 frontmatter 鍵，因此設定了 `context: fork`（以及 `agent`，如 `agent: Explore`）的技能透過入口呼叫時，同樣可以作為子代理 fork 執行。沿用的鍵為 `context`（僅 `fork`）、`agent` 與 `background`（僅在 `context: fork` 時）、`model`、`effort`（`low`、`medium`、`high`、`xhigh`、`max`）、`argument-hint` 與 `paths`。值會進行型別檢查，只捨棄無效的鍵。會變更權限或整個工作階段的鍵（`allowed-tools`、`disallowed-tools`、`hooks`）不會沿用，`shell`、`when_to_use`、`license` 等也不會沿用；`disable-model-invocation` 與 `user-invocable` 遵循 Skilvella 中「用法」的設定。其他用戶端的入口維持不變。如果呼叫帶有參數，入口會告知代理將參數作為已載入技能的輸入。僅對設定了 `context: fork` 的技能，入口會直接嵌入原始 `SKILL.md` 的內文，以取代透過 MCP 讀取內文的提示，並同時沿用 `arguments`。如果內文包含以 `!` 開頭的動態指令或 `CLAUDE_SKILL_DIR`、整個入口超過 2 MiB，或內文為空，則不會嵌入，仍使用原有的提示。由於 `~/.claude/skills` 也會被 Cursor 與 Grok 讀取，嵌入的內文對它們同樣可見。

GitHub Copilot（Copilot CLI 只會尋找 `~/.copilot/skills/<name>/SKILL.md`）與 Devin 也使用相同的連結方式與規則：不覆寫同名的既有項目，只移除 Skilvella 建立的連結，連結資料夾與受管理資料夾重疊時不同步。只有 Claude Code 會接手手動建立、指向 Codex 入口的連結。Copilot CLI 是否遵循 `disable-model-invocation`，以及 Devin 的搜尋深度，尚未確認。官方文件並未說明 Copilot CLI 是否套用技能的 `user-invocable: false`（VS Code 官方支援），因此在「僅自動選擇」下，CLI 中可能仍保留 `/name`。

Cursor 也會讀取 `~/.agents/skills` 與 `~/.claude/skills`，GitHub Copilot 會讀取 `~/.agents/skills`，Devin 會讀取 `~/.agents/skills` 與 `~/.copilot/skills`，因此啟用多個用戶端時，同一入口可能重複顯示。

Grok 也會讀取 Codex（`~/.agents/skills`）與 Claude Code（`~/.claude/skills`）的探索路徑，對於同名技能，優先順序為 `~/.grok/skills`、`~/.agents/skills`、`~/.claude/skills`。Codex 的入口會以 `agents/openai.yaml` 停止自動選擇，因此在 Grok 中，即使是「僅命令候選」的技能也會被自動選擇。如果你使用 Grok，請選取 Grok 作為同步目標。同樣地，`~/.agents/skills` 也會被 Grok 與 VS Code 中的 GitHub Copilot 讀取，因此如果選取 Codex 作為同步目標，「僅自動選擇」技能的命令可能會在這些用戶端中可見（Codex 的入口無法隱藏它）。

請在各技能的詳細頁面，或使用清單中的「用法」下拉選單來選擇模式。在清單中可以確認目前的模式並就地切換（批次操作使用同一個下拉選單）。MCP 不會傳回未公開技能的內容，且在同步成功之後，也會移除它們的候選入口。

如果你在清單中儲存進行期間按下瀏覽器的上一頁按鈕或重新載入，Skilvella 會先確認儲存結果，再顯示最新設定。因連線中斷而未被接受的請求會被取消，並在畫面上顯示確認結果。

| 模式 | 為自動選擇傳遞的名稱與說明 | 命令候選 |
| --- | --- | --- |
| 僅搜尋（預設） | 不傳遞 | 不顯示 |
| 僅命令候選 | 不傳遞 | 顯示 |
| 僅自動選擇 | 傳遞 | 用戶端允許時隱藏 |
| 自動選擇＋命令候選 | 傳遞 | 顯示 |

對於顯示命令候選的技能，各同步目標的呼叫命令（Codex 為 `$name`，其他用戶端為 `/name`）會顯示在清單中的技能名稱下方，以及詳細頁面的「用法」下。在「僅自動選擇」下，只會顯示無法隱藏命令的用戶端的命令（例如會顯示 Codex 的 `$name`，但不顯示 Claude Code 的 `/name`）。如果名稱包含小寫字母、數字與 `-` 以外的字元，則會變成 `skill-<id 的前 8 個字元>`，而如果存在同名的已公開技能，則會變成 `<name>-<id 的前 8 個字元>`，因此請使用所顯示的命令。沒有命令時，詳細頁面會顯示原因（僅搜尋、僅自動選擇因而沒有命令、未選擇同步目標、未公開或讀取錯誤）。在清單中從未公開切換為已公開的技能，其命令會在重新載入後出現。

在清單中勾選技能，在批次操作下選擇「用法」，然後按下「套用至所選項目」，即可一次變更多個技能的模式。「不變更」會保留目前的模式。你也可以同時變更公開狀態與標籤。

在「所有技能」下開啟「依來源批次設定」，可以選取多個來源，並以「套用至所選來源」一併變更公開狀態與用法。其範圍是執行時已註冊的所有頁面上的技能，不會沿用於之後新增的技能。預先檢查的數量依據掃描索引，且不包含遺失與錯誤的項目。結果會顯示已更新的數量與被排除的數量。公開時會重新檢查檔案，若因遺失、無法讀取、無效等原因而無法重新驗證，則所有項目的設定儲存都會被取消。設定會以單一交易儲存，原始技能不會改變。

「僅自動選擇」會在 Claude Code、Grok 與 GitHub Copilot 的入口中以 `user-invocable: false` 隱藏命令（技能會從 `/` 選單中消失，但模型仍可自動選擇它）。Codex、Cursor 與 Devin 無法隱藏命令，因此它們的入口與「自動選擇＋命令候選」相同（Codex 為 `agents/openai.yaml` 中的 `allow_implicit_invocation: true`）。儲存的值仍是原有的 `{"automatic":true,"command":false}`，沒有新的儲存格式，也不需要遷移。

原始內容的完整複本不會被隨時保有；內容會在需要時從 MCP 取得。未顯示在候選中的技能，可以使用僅限明確呼叫的 `$skilvella-search` 搜尋。你也可以直接使用 MCP 的 `search_skills`。

如果退回舊版本，這些入口會在該版本下一次同步時被移除，結果與「僅搜尋」相同。舊版本的清單會為這類技能顯示「設定未知。請選擇使用方式。」，其詳細頁面的選擇框中顯示「自動選擇＋命令候選」，但除非你變更，否則不會儲存。

用法模式對所有同步目標通用。入口位置如上表所示。當你將技能設為未公開或變更其模式時，不再需要的產物會被移到探索路徑之外（位於 `~/.agents`、`~/.claude`、`~/.grok`、`~/.cursor`、`~/.copilot` 與 `<Devin 設定>` 正下方的 `skilvella-staging` / `skilvella-retired`）。如果偵測到未知檔案或手動編輯，則不會覆寫，並在設定頁面顯示同步錯誤。如果因磁碟空間不足或強制結束而留下不完整的暫存檔案，它會停止並保護既有的正常索引。請檢查所顯示路徑的內容後再重試。停用整合會從探索路徑中移除它所擁有的入口。同步停止期間，先前的候選與自動選擇設定可能會殘留。原始檔案、公開狀態與編輯歷史紀錄不會改變。如果 Codex 的候選顯示沒有更新，請重新開啟候選選單或重新啟動 Codex。Claude Code 即使在執行中的工作階段，也會反映對 `~/.claude/skills` 的變更，但如果你是在工作階段開始之後才建立 `~/.claude/skills` 本身，請執行 `/reload-skills`。已載入現有對話中的內容無法移除。

## 顯示設定

在資料庫中，選取左側的資料夾並開啟「變更顯示名稱」，即可變更畫面上顯示的資料夾名稱。輸入內容（含前後空白）必須在 100 個字元以內，且不允許換行等控制字元。儲存時會去除前後空白，空值會還原為原始識別碼。顯示名稱儲存於應用程式內，實際的資料夾名稱、技能 ID、公開設定與編輯歷史紀錄都不會改變。允許重複的顯示名稱，但你已變更的名稱會與其原始識別碼一併顯示。

在管理介面的「設定」中，你可以將語言選擇為自動或九種語言之一（日文、英文、簡體中文、繁體中文、韓文、西班牙文、法文、德文、巴西葡萄牙文）。預設的「自動」會使用瀏覽器的語言設定。語言會在你選取時儲存，若已停用 JavaScript，請按下「儲存」。此選擇會依連接埠儲存在同一個瀏覽器中，已開啟的其他分頁會從其下次載入頁面時套用。舊版的語言設定，在你於同一個瀏覽器中以相同位址開啟管理介面時會被沿用。沿用需要 JavaScript。技能名稱、說明、內容、路徑與技術性錯誤詳細資訊會保留原文。系統匣與選單列的選單、`--help` 等命令列輸出、啟動訊息與錯誤，以及安裝程式（Setup）版的訊息方塊，也會以相同的九種語言顯示。這些語言會依下列順序決定：環境變數 `SKILVELLA_LANGUAGE`（例如 `ja`、`pt-BR`）→ `LC_ALL` → `LC_MESSAGES` → `LANG` → 作業系統顯示語言，若無法判斷則使用英文。MCP 工具名稱與說明為英文。

啟用 JavaScript 時，你可以從「自動」、「淺色」與「深色」中選擇主題。此選擇會儲存在瀏覽器中，「自動」會跟隨瀏覽器的色彩配置設定。

## 資料與備份

| 作業系統 | 預設資料位置 |
| --- | --- |
| Windows | `%LOCALAPPDATA%\Skilvella` |
| macOS | `~/Library/Application Support/Skilvella` |
| Linux | `$XDG_DATA_HOME/skilvella` 或 `~/.local/share/skilvella` |

`SKILL.md` 與參考檔案的事實來源是已註冊的資料夾。除了搜尋索引之外，資料資料夾的 `library.sqlite3` 也儲存標籤、分類、公開設定、已註冊位置、資料夾顯示名稱與編輯歷史紀錄。**如果你刪除整個資料庫，這些管理資料就會遺失。**

備份時，請先結束 Skilvella，然後同時複製資料資料夾與已註冊的資料夾。單靠資料庫無法還原目前的技能檔案。在另一台電腦上，已註冊來源的絕對路徑會不同，因此不支援直接共用資料庫以同時使用。

## 選項與疑難排解

```sh
skilvella --data-dir /absolute/path/to/data --port 7465 --no-watch
skilvella --help
```

- 如果連接埠已被占用，請結束既有的處理程序，或以 `--port` 變更。管理介面與 MCP 使用同一個連接埠。
- 如果從舊版 Windows 更新後管理介面沒有恢復，請在一般配置下啟動一次更新後的 `skilvella.exe`，或在 Toolport 管理下啟動一次啟動器。
- 如果舊版中斷的資料夾移動在啟動時無法復原，啟動會中止。原始資料與遷移記錄會被保留。
- 資料位置與技能註冊位置不能重疊。請在本機磁碟上指定各自獨立的資料夾。
- 在另一個分頁所做的編輯，在儲存時也會被偵測為衝突。請複製所保留的草稿，重新載入，並將其合併到最新內容中。
- 搜尋使用以空白分隔的 AND 與子字串比對。不包含以日文查詢依語意搜尋英文技能、嵌入模型與雲端同步。
- 即使來源資料夾離線，註冊資料與歷史紀錄也會保留。重新連線後請重新掃描。

連線僅限於 `127.0.0.1`。它設計用於你信任同一台電腦上的使用者與處理程序的環境。
