# Skilvella

[日本語](README.ja.md) | [English](README.md) | **简体中文** | [繁體中文](README.zh-TW.md) | [한국어](README.ko.md) | [Español](README.es.md) | [Français](README.fr.md) | [Deutsch](README.de.md) | [Português (Brasil)](README.pt-BR.md)

这是一款本地应用，可在浏览器中整理大量 `SKILL.md` 文件，并通过 MCP 只加载你需要的技能。无论技能有多少，它只公开三个 MCP 工具。

- 可按名称、描述、正文和标签进行关键词搜索，包括日语子串匹配。
- 支持文件夹注册、技能创建、正文编辑、标签与分类、批量操作，以及按技能切换 MCP 公开状态。
- 每次编辑前都会保存历史并可恢复，可检测与外部编辑的冲突，并检查重名、语法错误和文件缺失。
- 支持 Windows / macOS / Linux。请在同一台电脑上使用浏览器访问。

## 快速开始

在 Windows 上，运行 [SkilvellaApp-win-Setup.exe](https://skilvella.kagayoi.com/SkilvellaApp-win-Setup.exe)，然后从开始菜单启动“Skilvella”。安装程序（Setup）版会在安装时自行注册，使其在当前用户登录时启动。从已有的独立版（ZIP）切换时，请先从任务栏托盘图标退出旧版本（如果旧版本仍在运行，默认端口（7465）将无法使用，安装程序（Setup）版会显示相应提示并且不会启动）。ZIP 版的登录自启动注册会在安装时自动切换为安装程序（Setup）版，开始菜单中的“Skilvella”快捷方式也会随之指向安装程序（Setup）版。如果你曾禁用自启动，它仍保持禁用。卸载时也会移除指向安装程序（Setup）版的自启动注册。旧版本的文件夹不会被自动删除，如不再需要，请手动删除。如果你正在使用没有自动更新机制的旧版安装程序（Setup）（1.1.4 至 1.1.6），请用新的 Setup 重新安装一次。标准数据文件夹 `%LOCALAPPDATA%\Skilvella` 是共用的，卸载后仍会保留。安装程序版会自动更新（[应用更新](#app-updates)）。

如需使用 ZIP 版或 macOS 版，请下载对应的软件包（[Windows x64](https://skilvella.kagayoi.com/portable/Skilvella-windows-x86_64.zip) 或 [Mac Apple Silicon](https://skilvella.kagayoi.com/portable/Skilvella-macos-aarch64.tar.gz)，由 skilvella.kagayoi.com 提供）并解压。1.1.8 及更早的 ZIP 版和 macOS 版通过 GitHub 检查更新，该方式已不再使用，因此如果你正在使用这些版本，请手动重新安装一次新的软件包。

- Windows x64：将 `Skilvella-windows-x86_64.zip` 解压到你要长期使用的文件夹，然后启动 `skilvella.exe`。它在任务栏托盘中运行，不会打开终端，首次正常启动时会将“Skilvella”添加到当前用户的开始菜单。
- Mac Apple Silicon：解压 `Skilvella-macos-aarch64.tar.gz`，然后在终端中运行 `./skilvella`。
- 解压前，可以对照 [`SHA256SUMS.txt`](https://skilvella.kagayoi.com/portable/SHA256SUMS.txt) 校验软件包的 SHA-256。

Linux 或从源代码构建，请参阅[开发指南](docs/DEVELOPMENT.md)。

Skilvella 在 Windows 上会在任务栏托盘中显示图标，在 Mac 上会在菜单栏中显示图标。左键单击即可在默认浏览器中打开管理界面。右键单击（Mac 上为 Control 单击）可选择“打开管理界面”“检查更新”“重启服务”或“退出”。在 Windows 上，如果看不到图标，也请检查托盘的隐藏图标溢出区域。

“重启服务”会在同一进程、同一 URL 下重启 HTTP/MCP 服务器和文件监视。已保存的技能和设置会保留。重启期间的重复请求会被合并，重启会等待正在处理的 HTTP 操作完成。MCP 连接会断开，请从客户端重新连接。使用前，请重新加载已打开的管理页面。“退出”会关闭服务器和图标。

你也可以直接在 [http://127.0.0.1:7465/](http://127.0.0.1:7465/) 打开管理界面。MCP 端点是 `http://127.0.0.1:7465/mcp`。在没有显示器的环境中，请传入 `--no-tray`。在 Linux 上它不显示图标，作为 HTTP/MCP 服务器运行。

对于 Windows 独立版的目录布局，不带参数启动时会尝试注册为在当前用户登录时启动。如果已经注册，从其他位置启动可执行文件不会更改已注册的路径。你可以在 Windows“设置”→“应用”→“启动”中开启或关闭自启动。若本次启动不想注册，请传入 `--no-autostart`。对于由 Toolport 管理的自启动，请在 Toolport 一侧配置。

运行时不需要 Rust、Node.js、Python 或外部数据库服务器。从终端启动时，也可以在所附加的控制台中按 `Ctrl+C` 退出。

## 管理你的库

首次启动时，Skilvella 会自动检测被管理的文件夹。它会按顺序检查现有的 `~/.agents/skills`、`$CODEX_HOME/skills` 和 `~/.codex/skills`，如果都没有找到，则在数据文件夹旁边创建 `<data-folder-name>-skills`。如果候选文件夹中只包含由 Skilvella 生成的 Codex 调用入口，则会跳过该候选，这些入口本身也不计入被管理的技能。只有当数据文件夹中保存有这些入口的所有权记录时才是如此。如果你重新创建了数据文件夹，或用 `--data-dir` 指向了其他文件夹，之前生成并仍然保留的入口会被注册为普通技能。如果之前已经注册过来源，则以该配置为准并沿用。如果因读取入口所有权记录或候选时出现问题而无法确定自动检测结果，则保留已保存的自动注册目标。请在库左侧的文件夹列表中查看检测状态。

库是单一界面：左侧是被管理的文件夹列表，右侧是技能列表。点击“+ 添加文件夹”会打开操作系统的标准文件夹选择器；所选文件夹会原样注册并被扫描。文件不会被移动。你无需输入名称，文件夹名称会用作显示名称（之后可通过“更改显示名称”修改）。在无法打开对话框的环境（如 SSH 会话）中，请在“输入路径添加”下输入绝对路径。

在左侧选择一个文件夹，会显示它的位置、数量和标准扫描路径警告，以及“更改显示名称”和“停止管理”。对于默认文件夹，可通过“更改引用的文件夹”切换所引用的文件夹，并通过“浏览…”从对话框中选择。该设置在重启后仍然保留，“停止管理”不会删除文件。如果你选择的文件夹已被管理，或与某个被管理的文件夹存在父子关系，则会停止添加，并显示发生重叠的文件夹的名称。

通过添加、自动检测或外部编辑发现的新技能，只要可以读取，就会注册为**已开启 MCP 公开**。存在读取错误或 frontmatter 无效的技能保持未公开，即使修复后也不会自动公开。已有技能的公开状态不会因重新扫描或启动而改变（你设为未公开的技能绝不会被自动公开）。在 Windows 和 macOS 上，仅 ASCII 字母大小写不同的文件夹名会被视为同一个技能，其公开状态不会改变。如果你不想公开某个技能，请在添加文件夹后，在列表的“状态”列中选择“未公开”。在列表的“状态”列中选择“已公开”或“未公开”会立即保存。你也可以在单个技能页面或通过列表的批量操作来切换。切换为公开时会重新检查文件，缺失、有读取错误或 frontmatter 无效的技能不会被公开；所选项会被还原并显示原因。标签和分类不会改变。

库从一开始就列出所有文件夹的技能，并可就地搜索。直接包含 `.git` 目录或文件的文件夹，会作为来源（仓库）嵌套显示在该文件夹下，其余的归入“个人技能”。如果某个文件夹内部没有直接的来源仓库，而它本身就是 Git 仓库，则整个文件夹成为一个来源。常规列表显示当前存在的技能。旧的注册记录（例如移动之前的记录）会被保留，可在状态“未找到”或“全部”以及左侧的“清理不存在的技能记录”下查看。在“未找到”列表中，“批量删除缺失记录”会删除符合搜索条件的所有页面中的注册数据、设置和历史。此操作无法撤销。它不会更改实际文件，并且如果无法访问来源或路径存在，则会中止所有条目的删除。分类可在各技能的元数据中编辑。

Skilvella **不限深度、递归地**搜索已注册文件夹中的 `SKILL.md` 文件。即使找到了一个技能，它也会继续扫描更深的子目录。父技能和子技能使用不同的 ID 和公开设置分别管理，子技能的文件不包含在父技能的 MCP 公开范围内。符号链接、Windows 联接点（junction）、`.git`、`node_modules`、`target` 和 `.work` 会被排除。取消注册文件夹不会删除原始文件。如果你重新添加之前已停止管理的文件夹，其先前的管理数据（公开设置、标签、历史）会被恢复。同名的文件夹之间不会冲突。

保存正文会修改已注册位置中的实际文件。预览会禁用 HTML、图片加载和链接操作，也不会执行脚本。在外部编辑器中所做的更改会被自动监视。如果没有反映出来，请使用“重新扫描”。

出现读取错误时，请从库的“查看并修复读取错误”或左侧的“读取错误”打开跨文件夹的错误列表。打开技能名称或路径可查看原因，对于语法错误，请修改正文并保存。如果文件无法读取，请检查其位置、权限和字符编码，然后重新扫描。错误解决后，通知会消失。

## 应用更新

**安装程序（Setup）版**：默认开启自动更新。它会在启动时以及持续运行期间每 24 小时检查一次新版本，如有可用版本则下载。更新会在下次启动时自动应用，并以相同的设置重新启动。距离上次检查不满 24 小时时不会联网。如果检查或下载失败，则继续运行当前版本。你可以在“设置”的“应用更新”下通过“启动时自动更新”关闭此功能（该设置保存在数据文件夹（例如 `%LOCALAPPDATA%\Skilvella`）中的 `app-update.json` 里，不会更改技能库）。“检查更新”不受 24 小时间隔限制，立即检查；“安装更新”会下载更新并立即重启。更新信息从 `skilvella.kagayoi.com` 获取。

以下内容适用于独立版（ZIP）和 Mac。

你可以在“设置”的更新部分或托盘菜单的“检查更新”中，查看 skilvella.kagayoi.com 上最新的稳定版本。选择“安装更新”会通过 HTTPS 下载适用于 Windows x64 / Mac Apple Silicon 的软件包和 `SHA256SUMS.txt`，校验 SHA-256 后再应用。这需要操作系统自带的 `curl`，以及对可执行文件所在位置的写入权限。Linux 或其他 CPU 不支持应用内更新。

更新会等待正在处理的 HTTP 操作完成后再退出，然后以相同的启动参数和工作文件夹重新启动。请重新连接你的 MCP 客户端。如果软件包校验失败，则保留当前版本。如果应用更新后无法启动新进程，它会尝试恢复旧的可执行文件或 Toolport 的引用目标。发起更新的设置页面会在新版本响应后自动重新加载。如果你在应用重启前就已打开的旧设置页面上执行更新操作，系统会请你重新加载页面。

更新前可执行文件所在的同一位置会创建一个 `.skilvella-update-*` 文件夹，其中保留 `update.log`。在常规布局下，它还会存放用于恢复的 `previous-binary`。确认更新后运行正常且更新辅助程序已退出后，你可以删除此文件夹。

在 Toolport 的 `Skilvella-Latest.ps1` 管理下，现有版本会被保留，新版本的文件夹和校验信息会被添加，启动器的引用目标会被切换。更新辅助程序会一直运行到重启后的应用退出，因此请先退出 Skilvella，再删除更新文件夹。

当 Skilvella 由外部进程监视器启动时，你可能需要在该工具中重新启动它。如果无法获取 Toolport 的启动锁，则不会应用更新。如果没有启动，请重新运行启动器。包含日语等非 ASCII 字符的 Toolport 管理位置不支持应用内更新。常规的独立版布局不受此限制。

<a id="mcp-connection"></a>

## MCP 连接

请将以下 URL 注册到支持 Streamable HTTP 的客户端。

```text
http://127.0.0.1:7465/mcp
```

在 Toolport 中，将其注册为 HTTP 服务器并指定相同的 URL。请保持 Skilvella 运行。

| 工具 | 用途 |
| --- | --- |
| `search_skills` | 搜索已公开的技能，获取摘要和 ID |
| `load_skill` | 通过指定 ID 获取 `SKILL.md` 内容和参考文件列表 |
| `read_skill_file` | 按行获取技能下的 UTF-8 文本 |

对于 `load_skill`，请持续传入续取参数，直到 `next` 为 null，拼接内容后再按照其中的指示操作。列表通常每页 100 项，路径总量最多 8 KiB，但如果单个路径超过 8 KiB，则该路径会单独返回，因此响应会变大。请逐个获取技能及其所需的参考文件。对于参考文件，请使用 `read_skill_file` 获取所需行范围直到末尾的 `next_text_offset`，仅在需要更多行时才使用 `next_start_line`。同一行范围的字节分页按原样拼接，拼接不同行范围时会在其间插入换行。使用 `next_text_offset` 继续时，请保持 `start_line` 和 `max_lines` 不变；获取下一个行范围时，将 `start_line` 设为 `next_start_line`，并将 `text_offset` 重置为 0。换行符会像之前一样被规范化，末尾的换行符会被去掉。续取时，请将返回的 `revision` 指定为 `expected_revision`。如果文件在此期间发生了变化，请从头重新获取。

MCP 是只读的。它无法返回未公开的技能、frontmatter 无效的技能或缺失的技能的内容。也没有执行参考文件的功能。内容上限为 2 MiB，参考文本上限为 1 MiB。

仅凭 MCP 公开并不会改变代理仍会按标准方式发现并加载相同技能这一事实。为避免重复加载，请将技能放在代理的标准扫描路径之外，并通过库的“+ 添加文件夹”注册该位置。Skilvella 没有移动文件夹的功能。如果需要移动现有文件，请自行操作，然后重新注册新位置。Codex 的配置文件不会被编辑。更改标准扫描路径后，请重启 Codex。已加载到对话中的内容不会被移除。请单独检查自定义扫描设置和其他客户端。

## 自动选择与命令候选

请先使用采用 [MCP 连接](#mcp-connection)的客户端注册并验证 Skilvella。在“设置”的“调用入口同步”下，勾选同步目标（Codex、Claude Code、Grok；可多选）并保存，Skilvella 自身就会自动为各客户端同步调用入口。如果你在旧版本中启用过“Codex 集成”，它会被沿用，并选中 Codex。该功能在 Windows、macOS 和 Linux 上的工作方式相同，既不使用任务计划程序，也不使用任何单独的常驻进程。同步会在启动时、管理操作之后以及定期检查期间运行，并且服务重启后设置仍会保留。

| 同步目标 | 入口位置 | 向扫描暴露的方式 | 自动选择的控制 |
| --- | --- | --- | --- |
| Codex | `~/.agents/skills/skilvella/<name>` | 实际文件（Codex 会搜索嵌套文件夹） | `agents/openai.yaml` |
| Claude Code | `~/.claude/skilvella/skills/<name>` | 指向 `~/.claude/skills/<name>` 的链接（Windows 上为联接点，macOS 和 Linux 上为符号链接） | `disable-model-invocation` |
| Grok | `~/.grok/skills/skilvella/<name>` | 实际文件（Grok 会搜索嵌套文件夹） | `disable-model-invocation` |

Claude Code 只搜索 `~/.claude/skills` 正下方的一层，因此入口被放置在扫描路径之外，并为每个技能创建一个链接。如果 `~/.claude/skills` 中已存在同名的技能或链接，则不会覆盖，并将该名称显示为同步错误。你按照旧版本的指引，手动创建的从 `~/.claude/skills/<name>` 指向 `~/.agents/skills/skilvella/<name>` 的链接，会被重新指向 Claude Code 入口并接管管理，但仅限属于同步目标的名称。不属于同步目标的名称所对应的链接保持不变（如果你禁用 Codex，它们的引用目标就会消失）。为 Claude Code 禁用同步时，只会移除由 Skilvella 创建或接管的链接。如果你已将 `~/.claude/skills` 本身注册为被管理的文件夹，则不会执行同步。

Grok 也会读取 Codex（`~/.agents/skills`）和 Claude Code（`~/.claude/skills`）的扫描路径，对于同名技能，按 `~/.grok/skills`、`~/.agents/skills`、`~/.claude/skills` 的顺序优先。Codex 入口通过 `agents/openai.yaml` 停止自动选择，因此在 Grok 中，即使是“仅命令候选”的技能也会被自动选择。如果你使用 Grok，请将 Grok 选为同步目标。

请在各技能的详情页或通过列表中的“用法”选择模式。在列表中可以查看当前模式并就地切换。MCP 不会返回未公开技能的内容，同步成功后也会移除它们的候选入口。

如果在列表中保存进行期间按下浏览器的“后退”按钮或重新加载页面，Skilvella 会先确认保存结果，再显示最新设置。因连接中断而未被接受的请求会被取消，检查结果会显示在屏幕上。

| 模式 | 为自动选择传递的名称和描述 | 命令候选 |
| --- | --- | --- |
| 仅搜索（默认） | 不传递 | 不显示 |
| 仅命令候选 | 不传递 | 显示 |
| 自动选择＋命令候选 | 传递 | 显示 |

对于显示命令候选的技能，各同步目标的调用命令（Codex 为 `$name`，Claude Code 和 Grok 为 `/name`）会显示在列表中技能名称的下方以及详情页的“用法”下。如果名称包含小写字母、数字和 `-` 以外的字符，则会变为 `skill-<id 的前 8 个字符>`；如果存在同名的已公开技能，则会变为 `<name>-<id 的前 8 个字符>`，请使用所显示的命令。没有命令时，详情页会显示原因（仅搜索、未选择同步目标、未公开或读取错误）。在列表中从未公开切换为已公开的技能，其命令会在重新加载后出现。

在列表中勾选技能，在批量操作下选择“用法”，然后点击“应用到所选项”，即可一次更改多个技能的模式。“不更改”会保持当前模式。你也可以同时更改公开状态和标签。

在“全部技能”下打开“按来源批量设置”，可以选择多个来源，并通过“应用于所选来源”一并更改公开状态和用法。范围是运行时已注册的所有页面上的技能，不会延续到之后新增的技能。预检查的数量基于扫描索引，不包括缺失和错误的条目。结果会显示已更新的数量和被排除的数量。公开时会重新检查文件，如果因缺失、无法读取、无效等原因而无法重新验证，则所有条目的设置保存都会被取消。设置在单个事务中保存，原始技能不会被更改。

Codex 没有“启用自动选择但不在候选中显示”的单独设置，因此 Skilvella 提供对应的三种模式。即使采用自动选择，它也不会始终保留原始内容的完整副本；内容在需要时从 MCP 获取。未显示在候选中的技能，可以通过仅用于显式调用的 `$skilvella-search` 搜索。你也可以直接使用 MCP 的 `search_skills`。

用法模式对所有同步目标通用。入口位置见上表。当你取消公开某个技能或更改其模式时，不再需要的产物会被移到扫描路径之外（`~/.agents`、`~/.claude` 和 `~/.grok` 正下方的 `skilvella-staging` / `skilvella-retired`）。如果检测到未知文件或手动编辑，则不会覆盖，并在设置页面显示同步错误。如果因磁盘空间不足或强制退出而残留了不完整的临时文件，它会在保护现有完好索引的前提下停止。请检查所显示路径的内容，然后重试。禁用集成会从扫描路径中移除它所拥有的入口。同步停止期间，之前的候选和自动选择设置可能仍会保留。原始文件、公开状态和编辑历史不会改变。如果 Codex 的候选显示没有更新，请重新打开候选菜单或重启 Codex。Claude Code 即使在运行中的会话里也会反映对 `~/.claude/skills` 的更改，但如果你是在会话开始之后才创建了 `~/.claude/skills` 本身，请运行 `/reload-skills`。已加载到现有对话中的内容无法移除。

## 显示设置

在库中，选择左侧的文件夹并打开“更改显示名称”，即可更改屏幕上显示的文件夹名称。输入内容含首尾空白在内必须在 100 个字符以内，且不允许使用换行等控制字符。保存时会去除首尾空白，留空则恢复为原始标识符。显示名称保存在应用内，实际文件夹名称、技能 ID、公开设置和编辑历史不会改变。允许显示名称重复，但已更改的名称会与其原始标识符一并显示。

在管理界面的“设置”中，你可以将语言选择为自动或九种语言之一（日语、英语、简体中文、繁体中文、韩语、西班牙语、法语、德语、巴西葡萄牙语）。默认的“自动（浏览器语言）”使用浏览器的语言设置。选择语言时即会保存，如果禁用了 JavaScript，请点击“保存”。该选择按连接端口保存在同一浏览器中，已打开的其他标签页会从下次加载页面时应用。旧版本的语言设置，在你于同一浏览器中打开相同地址的管理界面时会被沿用。沿用需要 JavaScript。技能名称、描述、正文、路径和技术性错误详情保持原文。托盘和菜单栏菜单、`--help` 等命令行输出、启动消息和错误，以及安装程序（Setup）版的消息框，也以相同的九种语言显示。这些语言按环境变量 `SKILVELLA_LANGUAGE`（例如 `ja`、`pt-BR`）→ `LC_ALL` → `LC_MESSAGES` → `LANG` → 操作系统显示语言的顺序确定，如果无法确定，则使用英语。MCP 工具的名称和描述为英语。

启用 JavaScript 时，你可以在自动、浅色和深色中选择主题。选择会保存在浏览器中，“自动”会跟随浏览器的配色方案设置。

## 数据与备份

| 操作系统 | 默认数据位置 |
| --- | --- |
| Windows | `%LOCALAPPDATA%\Skilvella` |
| macOS | `~/Library/Application Support/Skilvella` |
| Linux | `$XDG_DATA_HOME/skilvella` 或 `~/.local/share/skilvella` |

`SKILL.md` 和参考文件的权威来源是已注册的文件夹。除搜索索引外，数据文件夹中的 `library.sqlite3` 还保存标签、分类、公开设置、已注册位置、文件夹显示名称和编辑历史。**如果你删除整个数据库，这些管理数据就会丢失。**

备份时，请先退出 Skilvella，然后同时复制数据文件夹和已注册的文件夹。仅有数据库无法恢复当前的技能文件。在另一台电脑上，已注册来源的绝对路径不同，因此不支持原样共享数据库用于同时使用。

## 选项与故障排除

```sh
skilvella --data-dir /absolute/path/to/data --port 7465 --no-watch
skilvella --help
```

- 如果端口被占用，请退出现有进程，或用 `--port` 更改端口。管理界面和 MCP 都使用同一个端口。
- 如果从旧版 Windows 更新后管理界面没有恢复，请在常规布局下启动一次更新后的 `skilvella.exe`，或在 Toolport 管理下启动一次启动器。
- 如果旧版本中断的文件夹移动无法在启动时恢复，则启动会中止。原始数据和迁移记录会被保留。
- 数据位置和技能注册位置不能重叠。请在本地磁盘上指定各自独立的文件夹。
- 在另一个标签页中所做的编辑，也会在保存时被检测为冲突。请复制保留下来的草稿，重新加载，并将其合并到最新内容中。
- 搜索使用以空白分隔的 AND 和子串匹配。不包括用日语查询按语义搜索英语技能、嵌入模型和云同步。
- 即使来源文件夹离线，注册数据和历史也会保留。重新连接后请重新扫描。

连接仅限于 `127.0.0.1`。它面向信任同一台电脑上的用户和进程的场景。
