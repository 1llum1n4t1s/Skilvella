# Skilvella

大量の `SKILL.md` をブラウザーで整理し、必要なスキルだけMCP経由で読み込むローカルアプリです。スキルの数にかかわらず、MCPツールは3つです。

- 名前・説明・本文・タグのキーワード検索。日本語の部分一致にも対応。
- フォルダー登録、新規作成、本文編集、タグ・カテゴリ、一括操作、MCP公開の切り替え。
- 編集前の履歴保存と復元、外部編集との競合検出、重複名・構文エラー・消失ファイルの確認。
- Windows / macOS / Linux。ブラウザーは同じPCから利用します。

## 起動

[GitHub Releases](https://github.com/1llum1n4t1s/Skilvella/releases/latest)から、お使いのOS向けの配布物を取得して展開してください。

- Windows x64: `Skilvella-windows-x86_64.zip` 内の `skilvella.exe` を起動します。
- Mac Apple Silicon: `Skilvella-macos-aarch64.tar.gz` を展開し、ターミナルで `./skilvella` を起動します。
- `SHA256SUMS.txt` に配布物のSHA-256を掲載しています。初回の配布物はコード署名・Macの公証を含みません。

Windowsではタスクトレイ、MacではメニューバーにSkilvellaのアイコンを表示します。アイコンを1回クリックすると、既定のブラウザーで管理画面が開きます。Windowsでアイコンが見えない場合は、トレイの「隠れているインジケーター」も確認してください。

管理画面は直接 [http://127.0.0.1:7465/](http://127.0.0.1:7465/) でも開けます。MCPの接続URLは `http://127.0.0.1:7465/mcp` です。画面のない環境では `--no-tray` を指定してください。Linuxではアイコンを表示せず、HTTP/MCPサーバーとして動作します。

Linux向けなど、ソースからビルドする場合は[開発手順](docs/DEVELOPMENT.md)を参照してください。生成される実行ファイルは、Windowsでは `target\release\skilvella.exe`、macOS / Linuxでは `./target/release/skilvella` です。実行時のRust・Node.js・Python・外部DBサーバーは不要です。終了は起動したターミナルの `Ctrl+C` です。

初回起動では、管理対象フォルダーを自動判定します。既存の `~/.agents/skills`、`$CODEX_HOME/skills`、`~/.codex/skills` の順に確認し、見つからない場合はデータフォルダーの隣に `<データフォルダー名>-skills` を作成します。以前から登録済みのソースがある場合は、その設定を優先して引き継ぎます。

「ソース」画面の「管理対象フォルダー」で、自動判定と任意フォルダーを切り替えられます。指定するフォルダーは事前に作成し、絶対パスを入力してください。設定は再起動後も保持します。切り替えてもスキルファイルは移動・削除しません。「追加のソース」から複数のフォルダーを併せて管理することもできます。

追加ソースの「専用dirへ移動して登録」は、元のフォルダーを専用フォルダーへ丸ごと移動し、有効なスキルをすべてMCP公開します。「登録のみ」や自動判定で見つかった新しいスキルは**MCP公開オフ**です。既存の非公開スキルを起動時に自動公開することはありません。個別画面や一覧の一括操作でも公開を切り替えられます。

登録したフォルダー内の `SKILL.md` を**階層数を制限せず再帰的に検索**します。スキルが見つかった後も、さらに深いサブディレクトリを走査します。親子のスキルは別々のID・公開設定で管理し、子のファイルは親のMCP公開範囲に含めません。シンボリックリンク・Windowsのジャンクション、`.git`・`node_modules`・`target`・`.work` は対象外です。ソースの登録解除では元のファイルを削除しません。同じエイリアスとパスで再登録すると管理情報を引き継ぎます。

本文の保存は登録先の実ファイルを変更します。プレビューではHTML・画像の読み込み・リンクの操作を無効にし、スクリプトを実行しません。外部エディターの変更は自動監視します。反映されない場合は「再スキャン」を使ってください。

## MCP接続

Streamable HTTP対応クライアントに次のURLを登録します。

```text
http://127.0.0.1:7465/mcp
```

ToolportではHTTPサーバーとして登録し、同じURLを指定します。Skilvellaは起動した状態にしてください。

| ツール | 用途 |
| --- | --- |
| `search_skills` | 公開中のスキルを検索し、概要とIDを取得 |
| `load_skill` | IDを指定して `SKILL.md` 本文と参照ファイル一覧を取得 |
| `read_skill_file` | スキル配下のUTF-8テキストを行単位で取得 |

MCPは読み取り専用です。未公開・不正なfrontmatter・消失スキルの本文は取得できません。参照ファイルを実行する機能もありません。本文は最大2 MiB、参照テキストは最大1 MiBです。

MCP公開だけでは、Codexが同じスキルを標準探索して読み込む状態は変わりません。二重読み込みを避けるには、先にMCP接続を登録・確認し、「ソース」画面で標準探索対象のソースを「移動してMCPで使う」から専用フォルダーへ移行してください。**原本をフォルダー丸ごと移動し、有効なスキルをすべてMCP公開します。元の場所には残りません。** コピーだけでは元のスキルが直接読み込まれ続けます。Codexの設定ファイルは編集しません。

既定の移行先は、Windowsでは `%LOCALAPPDATA%\Skilvella-library`、macOSでは `~/Library/Application Support/Skilvella-library`、Linuxでは `$XDG_DATA_HOME/skilvella-library`（未指定時は `~/.local/share/skilvella-library`）です。`--data-dir` 指定時は、そのデータフォルダーの兄弟に `<データフォルダー名>-library` を使います。新規登録ではその配下のソース名を移動先とし、既存ソースでは移動先の絶対パスを入力できます。初回にスキルが見つからない場合の管理先 `<データフォルダー名>-skills` とは別の場所です。

移動先は同じボリューム内で、まだ存在しないフォルダーに限ります。空でも既存の移動先は拒否します。推奨する専用フォルダーは移行時に必要なら作成します。任意の移動先を指定する場合は、その親フォルダーを事前に用意してください。標準探索先の中への移動、リンクを含むフォルダーなど安全に移動できない対象も拒否します。移動では同じソース名・スキルIDを維持し、タグ・編集履歴・親子階層・相対参照を引き継ぎます。管理対象ソースを移行した場合は、その設定を移動先へ固定します。登録解除は移動の取り消しにはなりません。

通常のGit cloneは `.git` フォルダーも一緒に移動します。外部のGit管理領域を指すworktreeなど、`.git` が参照ファイルになっているものは拒否します。本文・スクリプト・設定内の絶対パスや外部からの参照は書き換えません。元の場所を絶対パスで参照している場合は、移行先に合わせた更新が必要です。

**移行後はCodexを再起動してください。** 標準探索から外れると `$スキル名` による直接呼び出しの対象からも外れるため、以後はMCPの検索でスキルを取得します。すでに会話へ読み込まれた内容は消せません。画面の移行成功はファイル移動とMCP公開の結果で、再起動後の実際のモデルのコンテキストを確認した表示ではありません。独自の探索設定や他クライアントは別途確認してください。エラー時は現在の登録先・元フォルダー・移動先・公開状態を確認してください。

Gitリポジトリの一部、Git worktree・外部共有参照、リンク、移行後も内部に標準スキル探索フォルダーが残る構成は、自動移行の対象外です。通常のGitクローンは、リポジトリ全体が移行対象のフォルダー内に収まる場合にそのまま保持します。

## データとバックアップ

| OS | 既定のデータ保存先 |
| --- | --- |
| Windows | `%LOCALAPPDATA%\Skilvella` |
| macOS | `~/Library/Application Support/Skilvella` |
| Linux | `$XDG_DATA_HOME/skilvella` または `~/.local/share/skilvella` |

`SKILL.md` と参照ファイルの正本は登録フォルダーです。データフォルダーの `library.sqlite3` には検索索引に加え、タグ・カテゴリ・公開設定・登録先・編集履歴も保存します。**DB全体を削除すると、これらの管理情報を失います。**

バックアップはSkilvellaを終了してから、データフォルダーと登録フォルダーの両方をコピーしてください。DBだけでは現在のスキルファイルを復元できません。別PCでは登録元の絶対パスが異なるため、DBをそのまま共有しての同時利用は対象外です。

## オプションとトラブルシュート

```sh
skilvella --data-dir /absolute/path/to/data --port 7465 --no-watch
skilvella --help
```

- ポートが使用中なら、既存プロセスを終了するか `--port` で変更します。管理画面とMCPの両方に同じポートを使います。
- データ保存先とスキル登録先は重ねられません。ローカルディスク上の別フォルダーを指定してください。
- 別タブで編集した場合も保存時に競合を検出します。保持された下書きをコピーし、再読み込みして最新の内容へ統合してください。
- 検索は空白区切りのAND・部分一致です。日本語から英語を意味で探す検索、埋め込みモデル、クラウド同期は含みません。
- 元フォルダーがオフラインになっても登録情報と履歴は保持します。再接続後に再スキャンしてください。

接続は `127.0.0.1` 限定です。同じPCの利用者・プロセスを信頼する用途を想定しています。
