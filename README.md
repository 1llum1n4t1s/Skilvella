# Skilvella

大量の `SKILL.md` をブラウザーで整理し、必要なスキルだけMCP経由で読み込むローカルアプリです。スキルの数にかかわらず、MCPツールは3つです。

- 名前・説明・本文・タグのキーワード検索。日本語の部分一致にも対応。
- フォルダー登録、新規作成、本文編集、タグ・カテゴリ、一括操作、MCP公開の切り替え。
- 編集前の履歴保存と復元、外部編集との競合検出、重複名・構文エラー・消失ファイルの確認。
- Windows / macOS / Linux。ブラウザーは同じPCから利用します。

## 起動

[GitHub Releases](https://github.com/1llum1n4t1s/Skilvella/releases/latest)から、お使いのOS向けの配布物を取得して展開してください。

- Windows x64: `Skilvella-windows-x86_64.zip` 内の `skilvella.exe` を起動します。
- Mac Apple Silicon: `Skilvella-macos-aarch64.tar.gz` を展開し、ターミナルで `./skilvella` を起動します。
- `SHA256SUMS.txt` に配布物のSHA-256を掲載しています。初回の配布物はコード署名・Macの公証を含みません。

Windowsではタスクトレイ、MacではメニューバーにSkilvellaのアイコンを表示します。左クリックすると、既定のブラウザーで管理画面が開きます。右クリック（MacではControl＋クリックも可）で「管理画面を開く」「更新を確認」「サービスを再起動」「終了」を選べます。Windowsでアイコンが見えない場合は、トレイの「隠れているインジケーター」も確認してください。

「サービスを再起動」は、同じプロセス・URLでHTTP/MCPサーバーとファイル監視を起動し直します。保存済みのスキルや設定は保持します。再起動中の重複要求はまとめ、処理中のHTTP操作の完了を待ちます。MCP接続は切断されるため、クライアントから再接続してください。開いている管理画面は再読み込みしてから操作してください。「終了」はサーバーとアイコンを終了します。

管理画面は直接 [http://127.0.0.1:7465/](http://127.0.0.1:7465/) でも開けます。MCPの接続URLは `http://127.0.0.1:7465/mcp` です。画面のない環境では `--no-tray` を指定してください。Linuxではアイコンを表示せず、HTTP/MCPサーバーとして動作します。

Linux向けなど、ソースからビルドする場合は[開発手順](docs/DEVELOPMENT.md)を参照してください。実行時のRust・Node.js・Python・外部DBサーバーは不要です。起動したターミナルの `Ctrl+C` でも終了できます。

初回起動では、管理対象フォルダーを自動判定します。既存の `~/.agents/skills`、`$CODEX_HOME/skills`、`~/.codex/skills` の順に確認し、見つからない場合はデータフォルダーの隣に `<データフォルダー名>-skills` を作成します。Skilvellaが生成したCodexの呼び出し入口だけがある候補は飛ばし、入口自体は管理対象のスキルに含めません。以前から登録済みのソースがある場合は、その設定を優先して引き継ぎます。入口の所有記録や候補の読み取りに問題があって自動判定を確定できない場合は、保存済みの自動登録先を維持します。「フォルダー」画面で検出状態を確認してください。

「フォルダー」画面で、管理中のフォルダーと現在の場所を確認できます。「フォルダーを追加」は既存のフォルダーを管理対象に加える操作で、ファイルは移動しません。既定のフォルダーの参照先だけを切り替える場合は、その登録の「参照するフォルダーを変更」を開いて指定します。設定は再起動後も保持し、「管理から外す」でもファイルは削除しません。

追加や自動判定で見つかった新しいスキルは**MCP公開オフ**です。既存の非公開スキルを起動時に自動公開することはありません。個別画面や一覧の一括操作で公開を切り替えられます。

ライブラリは最初に取得元リポジトリを選び、その中で検索・管理します。登録ソース直下の `.git` ディレクトリまたはファイルを持つフォルダーを取得元としてまとめ、それ以外は「個人スキル」にまとめます。直下に取得元リポジトリがないソース自体がGitリポジトリなら、その全体を1つの取得元にします。カードの登録件数には「見つからない」スキルも含み、該当件数を併記します。カテゴリは各スキルの管理情報から編集できます。

登録したフォルダー内の `SKILL.md` を**階層数を制限せず再帰的に検索**します。スキルが見つかった後も、さらに深いサブディレクトリを走査します。親子のスキルは別々のID・公開設定で管理し、子のファイルは親のMCP公開範囲に含めません。シンボリックリンク・Windowsのジャンクション、`.git`・`node_modules`・`target`・`.work` は対象外です。ソースの登録解除では元のファイルを削除しません。同じエイリアスとパスで再登録すると管理情報を引き継ぎます。

本文の保存は登録先の実ファイルを変更します。プレビューではHTML・画像の読み込み・リンクの操作を無効にし、スクリプトを実行しません。外部エディターの変更は自動監視します。反映されない場合は「再スキャン」を使ってください。

## アプリの更新

「設定」の更新欄、またはトレイメニューの「更新を確認」からGitHubの最新安定版を確認できます。「更新をインストール」を選ぶと、Windows x64 / Mac Apple Silicon向けの配布物と `SHA256SUMS.txt` をHTTPSで取得し、SHA-256を照合してから適用します。OS同梱の `curl` と実行ファイルの保存先への書込み権限が必要です。Linuxとその他のCPUではアプリ内適用に対応しません。

更新は処理中のHTTP操作の完了を待って終了し、同じ起動引数・作業フォルダーで再起動します。MCPクライアントは再接続してください。照合失敗時は現在の版を維持し、再起動の開始に失敗した場合は以前の実行ファイルを復元します。配布物はGitHubのHTTPSと公開チェックサムに基づいて検証します。コード署名による検証ではありません。

実行ファイルの隣の `.skilvella-update-*` には復旧用の旧実行ファイルと `update.log` を残します。更新後の動作を確認した後で削除できます。Toolportの `Skilvella-Latest.ps1` 管理下では、新版のフォルダーと検証情報を追加し、ランチャーのキャッシュ参照も切り替えます。既存の版は上書きしません。

外部のプロセス監視ツールで起動している場合は、そのツール側で再起動が必要になることがあります。Toolportの起動ロックを取得できない場合は更新を適用しません。起動しない場合はランチャーを再実行してください。日本語など非ASCII文字を含むToolport管理先はアプリ内適用に対応しません。通常の単体配置はこの制限の対象外です。

## MCP接続

Streamable HTTP対応クライアントに次のURLを登録します。

```text
http://127.0.0.1:7465/mcp
```

ToolportではHTTPサーバーとして登録し、同じURLを指定します。Skilvellaは起動した状態にしてください。

| ツール | 用途 |
| --- | --- |
| `search_skills` | 公開中のスキルを検索し、概要とIDを取得 |
| `load_skill` | IDを指定して `SKILL.md` 本文と参照ファイル一覧を取得 |
| `read_skill_file` | スキル配下のUTF-8テキストを行単位で取得 |

MCPは読み取り専用です。未公開・不正なfrontmatter・消失スキルの本文は取得できません。参照ファイルを実行する機能もありません。本文は最大2 MiB、参照テキストは最大1 MiBです。

MCP公開だけでは、Codexが同じスキルを標準探索して読み込む状態は変わりません。二重読み込みを避けるには、Codexの標準探索先以外にスキルを配置し、「フォルダー」画面でその場所を登録してください。Skilvellaにフォルダーを移動する機能はありません。既存ファイルの移動が必要な場合は自分で行い、参照先を登録し直してください。Codexの設定ファイルは編集しません。標準探索先を変更した後はCodexを再起動してください。すでに会話へ読み込まれた内容は消えません。独自の探索設定や他クライアントは別途確認してください。

旧版で中断したフォルダー移動の記録がある場合に限り、起動時の復旧処理を維持しています。フォルダーの同一性を確認できない場合は起動を止め、元データと記録を保持します。

## Codexの自動選択とコマンド候補

先に [MCP接続](#mcp接続) をCodexへ登録・確認してください。「設定」の「Codex連携」を有効にすると、Skilvella本体がCodex用の呼び出し入口を自動同期します。Windows／macOS／Linux共通で、タスクスケジューラや別の常駐プロセスは使いません。同期は起動時・管理操作後・定期確認時に実行し、サービスの再起動後も設定を維持します。

各スキルの詳細画面、または取得元を選んだ一覧の「Codexでの使い方」で選びます。一覧では現在のモードを確認し、その場で切り替えられます。MCPは非公開スキルの本文を返さず、正常な同期後にはその候補用入口も外します。

一覧で保存中にブラウザーの「戻る」や再読み込みを行った場合は、保存結果を確認してから最新の設定を表示します。通信が途切れて未受付だった要求は取り消し、確認結果を画面に表示します。

| モード | 自動選択用の名前・説明 | コマンド候補 |
| --- | --- | --- |
| 検索のみ（既定） | 渡さない | 表示しない |
| コマンド候補のみ | 渡さない | 表示する |
| 自動選択＋コマンド候補 | 渡す | 表示する |

取得元を選んだ一覧でスキルにチェックを付け、一括操作の「Codexでの使い方」を選んで「選択項目に適用」を押すと、複数スキルのモードをまとめて変更できます。「変更しない」なら現在のモードを維持します。公開状態・タグも同時に変更できます。

取得元カードでは複数の取得元を選択し、「選択した取得元に適用」で公開状態とCodexでの使い方をまとめて変更できます。対象は実行時に登録されている全ページのスキルで、今後の追加分には引き継ぎません。事前の対象件数はスキャン索引に基づき、不在・エラーの項目を除外します。結果には更新件数と対象外件数を表示します。公開時はファイルを再確認し、不在・読み取り不能・不正なファイルなどで再検証できない場合は全件の設定保存を取り消します。設定は一つのトランザクションで保存し、スキルの原本は変更しません。

Codexには「自動選択を有効にして候補だけ隠す」独立した設定がないため、対応する3モードを提供します。自動選択でも原本の全文を常時複製するのではなく、必要なときにMCPから取得します。候補に表示しないスキルは、明示呼び出し専用の `$skilvella-search` から検索できます。MCPの `search_skills` を直接使うこともできます。

入口の保存先は利用者ホームの `.agents/skills/skilvella` です。公開解除・モード変更時に不要になった生成物は探索先の外へ退避します。未知のファイルや手編集を検出した場合は上書きせず、設定画面に同期エラーを表示します。容量不足や強制終了で未完の一時ファイルが残った場合も、既存の正常な索引を保護して停止します。表示されたパスの内容を確認してから再試行してください。連携を無効にすると、この連携が所有する入口を探索先から外します。同期が停止している間は以前の候補や自動選択設定が残る場合があります。原本・公開状態・編集履歴は変更しません。Codexの候補表示が更新されない場合は、候補メニューを開き直すかCodexを再起動してください。既存会話に読み込まれた内容は消せません。

## 表示設定

「フォルダー」の各カードで「表示名を変更」を開くと、画面上のフォルダー名を変更できます。表示名は100文字以内で、改行などの制御文字は使えません。前後の空白は取り除き、空欄で保存すると元の識別子に戻ります。表示名はアプリに保存され、実際のフォルダー名・スキルID・公開設定・編集履歴は変わりません。同じ表示名も使えますが、変更した名前には元の識別子を併記します。

管理画面の「設定」で言語とテーマを変更できます。Toolportと同じ9言語（英語、日本語、簡体字、繁体字、韓国語、スペイン語、フランス語、ドイツ語、ブラジルポルトガル語）に対応し、初期値はブラウザーの言語に合わせる自動です。スキル名・説明・本文・パスと技術的なエラー詳細は原文を保持します。ネイティブのトレイメニューは日本語です。テーマは自動・ライト・ダークから選び、自動ではブラウザーの配色設定に追従します。表示設定はブラウザー内に保存され、ページ移動や再読み込み後も保持します。

## データとバックアップ

| OS | 既定のデータ保存先 |
| --- | --- |
| Windows | `%LOCALAPPDATA%\Skilvella` |
| macOS | `~/Library/Application Support/Skilvella` |
| Linux | `$XDG_DATA_HOME/skilvella` または `~/.local/share/skilvella` |

`SKILL.md` と参照ファイルの正本は登録フォルダーです。データフォルダーの `library.sqlite3` には検索索引に加え、タグ・カテゴリ・公開設定・登録先・フォルダーの表示名・編集履歴も保存します。**DB全体を削除すると、これらの管理情報を失います。**

バックアップはSkilvellaを終了してから、データフォルダーと登録フォルダーの両方をコピーしてください。DBだけでは現在のスキルファイルを復元できません。別PCでは登録元の絶対パスが異なるため、DBをそのまま共有しての同時利用は対象外です。

## オプションとトラブルシュート

```sh
skilvella --data-dir /absolute/path/to/data --port 7465 --no-watch
skilvella --help
```

- ポートが使用中なら、既存プロセスを終了するか `--port` で変更します。管理画面とMCPの両方に同じポートを使います。
- 古いWindows版からの更新後に管理画面が復帰しない場合は、通常配置では更新済みの `skilvella.exe` を、Toolport管理下ではランチャーを一度起動してください。自動再起動の修正は更新元のプロセスにも必要なため、旧版からの初回更新では手動起動が必要になる場合があります。
- データ保存先とスキル登録先は重ねられません。ローカルディスク上の別フォルダーを指定してください。
- 別タブで編集した場合も保存時に競合を検出します。保持された下書きをコピーし、再読み込みして最新の内容へ統合してください。
- 検索は空白区切りのAND・部分一致です。日本語から英語を意味で探す検索、埋め込みモデル、クラウド同期は含みません。
- 元フォルダーがオフラインになっても登録情報と履歴は保持します。再接続後に再スキャンしてください。

接続は `127.0.0.1` 限定です。同じPCの利用者・プロセスを信頼する用途を想定しています。
