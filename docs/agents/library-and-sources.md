# Libraryの操作と登録フォルダー

- スキル管理の同期ファイルI/OとSQLite操作は `src/library.rs` に置き、非同期ハンドラーからの読み取りは `AppState::run`、変更はCodex入口同期を待つ `AppState::run_mut` を通してください。Codex入口の生成・復旧はLibraryの操作ロックと所有権検証を通し、詳細は [Codex連携の設計](../../DESIGN.md#codexの呼び出し入口) を参照してください。
- ファイルを移動する新規操作は提供しません。許可するのは、ファイルを動かさず登録の場所だけを付け替える `Library::relocate_source`（`POST /sources/location`）だけで、登録と共通の `checked_source_root` と他の有効なフォルダーとの重複・親子の検査、操作ロック、`AppState::run_mut` を通してください。
- 同期の停止条件（有効なソースを開けないと同期全体を止める `export_codex` の検査）は変えず、読み取れないフォルダーの印（`source_unavailable:<alias>`）は走査時にだけ書き、画面の描画で全フォルダーを `read_dir` しないでください。
- 旧版の移行記録の起動時復旧はLibraryの操作ロック・ディレクトリ同一性検査を通してください。通常の走査で未完了の移行を修復する経路は追加しないでください。
- 公開判定、親子スキルの境界、パス検査、競合検出、履歴保存を迂回する別の読書き経路を追加しないでください。変更時は [設計の不変条件](../../DESIGN.md#重要な不変条件) を確認してください。
- スキル数に比例してMCPツールを増やさず、既存の検索・本文取得・参照取得の3ツールを入口にしてください。MCPからの書込み・ファイル実行は提供しません。
