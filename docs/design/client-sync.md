# 同期先クライアントと入口の配置

[DESIGN.md](../../DESIGN.md) から分割した詳細です。Codexの入口の基本方針は [codex-entrypoints.md](codex-entrypoints.md) を参照してください。

同期先はCodex・Claude Code・Grok・Cursor・GitHub Copilot・Devinから複数選択でき、各クライアントの有効状態・件数・エラーを `codex_sync`（旧版と共通）・`claude_sync`・`grok_sync`・`cursor_sync`・`copilot_sync`・`devin_sync` に分けて保存します。キーがない旧データは、Codexの設定だけを引き継ぎ、他は無効とみなします。使い方のモードと生成する入口の本文は全クライアントで共通で、frontmatterはClaude Codeだけが原本の一部を引き継ぎ、他は name・description と自動選択の表し方だけです。入口の本文には、呼び出しに引数があれば（Claude Codeは末尾に `ARGUMENTS:` 行として付け足します）読み込んだスキルの引数の受け皿に使う旨の英文1文を全クライアント共通で加えます。Claude Codeの入口へ引き継ぐ許可リストのキーは、`context`（値 `fork` のみ）、`agent` と `background`（`context: fork` のときだけ）、`model`、`effort`（low・medium・high・xhigh・max）、`argument-hint`、`paths` です。値は型を検査し、不正なキーだけを捨てます。目的は、`context: fork` と `agent: Explore` を持つスキルを入口経由で呼んでも、Claude Codeがサブエージェントとして fork 実行できるようにすることです。`allowed-tools`・`disallowed-tools`・`hooks` は権限やセッション全体を変え、`hooks` などは入口のフォルダーを指してしまうため引き継ぎません。`shell`・`arguments`・`when_to_use`・`license` なども引き継がず、`disable-model-invocation`・`user-invocable` はSkilvellaの「使い方」の設定を正本とします。他のクライアントはこれらのキーの扱いを確認できていないため、従来どおりです。自動選択の表し方は、Codexは `agents/openai.yaml`、Claude Code・Grok・Cursor・GitHub Copilotは `disable-model-invocation: true`、Devinは `triggers: [user]` で自動選択を止めます。生成先は記録済みの `~/.agents/skills` から求めた利用者ホームを共有し、Codexは `~/.agents/skills/skilvella`、Grokは `~/.grok/skills/skilvella`、Cursorは `~/.cursor/skills/skilvella`、Claude Codeは `~/.claude/skilvella/skills`、GitHub Copilotは `~/.copilot/skilvella/skills`（`COPILOT_HOME` には従いません）です。Devinは設定フォルダー（Windowsは `%APPDATA%\devin`、macOS・Linuxは `~/.config/devin`）の `skilvella/skills` です。同期中に環境変数を読まないよう、Devinの設定フォルダーは起動時に `devin_config_dir` として記録します（`Library::open_for_user` はホームから既定値を導出し、本体は `open_for_user_with_devin` で `%APPDATA%` から求めた値を渡します）。入口の名前（フォルダー名）は英小文字・数字・`-` の64字以内に正規化済みで、Cursor・GitHub Copilotの名前の制約を満たします。退避・ステージは生成先の2階層上（`~/.agents`・`~/.claude`・`~/.grok`・`~/.cursor`・`~/.copilot`・Devinの設定フォルダー）にある `skilvella-staging` / `skilvella-retired` に置き、復旧・清掃の前にクライアントごとの生成先の末尾を照合します。1クライアントの同期失敗で他のクライアントを止めません。全クライアントの生成入口は、Codexと同じく原本の走査から除外します。

Claude Code・GitHub Copilot・Devinは、生成物を所有フォルダーで公開し、探索先にはスキルごとのリンク（Windowsはジャンクション、macOS・Linuxはシンボリックリンク）だけを置きます。Cursorはリンクを辿らないため、Grokと同じ実ファイル配置です。リンクの記録・上書き拒否と、設定画面でのクライアント検出表示は [client-links.md](client-links.md) にあります。

所有元と生成物のハッシュはデータフォルダーの `codex-index/manifest.json`（他のクライアントは `claude-index`・`grok-index`・`cursor-index`・`copilot-index`・`devin-index`）に保持し、展開先のリンク・管理外ファイル・手編集を拒否します。変更時は既知の生成物をCodex探索先の外へ退避して再生成し、原本と公開状態を変更しません。同期失敗は管理画面へ表示し、HTTP/MCPサービスを止めません。利用者が実際に選択したか、Codexの既存会話へ何が読み込まれたかは、この設定と生成物だけでは観測できません。
