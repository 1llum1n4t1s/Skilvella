# 同期先クライアントと入口の配置

[DESIGN.md](../../DESIGN.md) から分割した詳細です。Codexの入口の基本方針は [codex-entrypoints.md](codex-entrypoints.md) を参照してください。

同期先はCodex・Claude Code・Grok・Cursor・GitHub Copilot・Devinから複数選択でき、各クライアントの有効状態・件数・エラーを `codex_sync`（旧版と共通）・`claude_sync`・`grok_sync`・`cursor_sync`・`copilot_sync`・`devin_sync` に分けて保存します。キーがない旧データは、Codexの設定だけを引き継ぎ、他は無効とみなします。使い方のモードと生成する入口の本文は、Claude Codeの `context: fork` の入口を除き全クライアントで共通です。その入口は、原本の `SKILL.md` の本文をそのまま埋め込みます。案内文方式は親の文脈を節約するためですが、fork のスキル本文は fork 先の担当にしか届かないのでその理由が当てはまらず、また fork 先が案内文を無視して本体に従わない事例があったためです。埋め込みの前に「埋め込み済みのため `load_skill` で読み直さず、相対リンク・`references`・`scripts` は入口フォルダーに無いので固定 id で `read_skill_file` を使う」旨の前置きを、後ろに引数（`ARGUMENTS:` 行）の扱いと `load_skill` 手順を除くMCP案内を付けます。次のいずれかのときは埋め込まず、従来の案内文に戻ります。本文が `!` による動的コマンド（直前が行頭・空白・記号のインライン `` !`…` ``、または本文のどこか（行頭に限らず、引用・箇条書きの中も含む）にある ```!（`~~~!` も含み、フェンス文字と `!` の間の空白も可）。Claude Codeのブロック構文は本文中のどこでも一致するため。`panic!` のように英数字の直後の `!` は対象外）を含む（ファイルやスクリプトの実行機能を持たない原則を守るため。入口に置くとClaude Codeが許可確認なしに実行するため）、`CLAUDE_SKILL_DIR` を含む（入口のフォルダーを指して誤った値になるため）、入口全体が2 MiBを超える、本文が空。`$ARGUMENTS`・`$0`・`$name` の置換はClaude Codeが行い、埋め込む入口に限り frontmatter の `arguments`（空白区切りの文字列か文字列の配列）も引き継ぎます。`~/.claude/skills` はCursor・Grokも読むため、埋め込んだ本文はそれらにも見えます。frontmatterはClaude Codeだけが原本の一部を引き継ぎ、他は name・description と自動選択の表し方だけです。入口の本文には、呼び出しに引数があれば（Claude Codeは末尾に `ARGUMENTS:` 行として付け足します）読み込んだスキルの引数の受け皿に使う旨の英文1文を全クライアント共通で加えます。Claude Codeの入口へ引き継ぐ許可リストのキーは、`context`（値 `fork` のみ）、`agent` と `background`（`context: fork` のときだけ）、`model`、`effort`（low・medium・high・xhigh・max）、`argument-hint`、`paths` です。値は型を検査し、不正なキーだけを捨てます。目的は、`context: fork` と `agent: Explore` を持つスキルを入口経由で呼んでも、Claude Codeがサブエージェントとして fork 実行できるようにすることです。`allowed-tools`・`disallowed-tools`・`hooks` は権限やセッション全体を変え、`hooks` などは入口のフォルダーを指してしまうため引き継ぎません。`shell`・`when_to_use`・`license` なども引き継がず（`arguments` は本文を埋め込む入口だけ引き継ぎます）、`disable-model-invocation`・`user-invocable` はSkilvellaの「使い方」の設定を正本とします。他のクライアントはこれらのキーの扱いを確認できていないため、従来どおりです。自動選択の表し方は、Codexは `agents/openai.yaml`、Claude Code・Grok・Cursor・GitHub Copilotは `disable-model-invocation: true`、Devinは `triggers: [user]` で自動選択を止めます。生成先は記録済みの `~/.agents/skills` から求めた利用者ホームを共有し、Codexは `~/.agents/skills/skilvella`、Grokは `~/.grok/skills/skilvella`、Cursorは `~/.cursor/skills/skilvella`、Claude Codeは `~/.claude/skilvella/skills`、GitHub Copilotは `~/.copilot/skilvella/skills`（`COPILOT_HOME` には従いません）です。Devinは設定フォルダー（Windowsは `%APPDATA%\devin`、macOS・Linuxは `~/.config/devin`）の `skilvella/skills` です。同期中に環境変数を読まないよう、Devinの設定フォルダーは起動時に `devin_config_dir` として記録します（`Library::open_for_user` はホームから既定値を導出し、本体は `open_for_user_with_devin` で `%APPDATA%` から求めた値を渡します）。入口の名前（フォルダー名）は英小文字・数字・`-` の64字以内に正規化済みで、Cursor・GitHub Copilotの名前の制約を満たします。退避・ステージは生成先の2階層上（`~/.agents`・`~/.claude`・`~/.grok`・`~/.cursor`・`~/.copilot`・Devinの設定フォルダー）にある `skilvella-staging` / `skilvella-retired` に置き、復旧・清掃の前にクライアントごとの生成先の末尾を照合します。1クライアントの同期失敗で他のクライアントを止めません。全クライアントの生成入口は、Codexと同じく原本の走査から除外します。

Claude Code・GitHub Copilot・Devinは、生成物を所有フォルダーで公開し、探索先にはスキルごとのリンク（Windowsはジャンクション、macOS・Linuxはシンボリックリンク）だけを置きます。Cursorはリンクを辿らないため、Grokと同じ実ファイル配置です。リンクの記録・上書き拒否と、設定画面でのクライアント検出表示は [client-links.md](client-links.md) にあります。

所有元と生成物のハッシュはデータフォルダーの `codex-index/manifest.json`（他のクライアントは `claude-index`・`grok-index`・`cursor-index`・`copilot-index`・`devin-index`）に保持し、展開先のリンク・管理外ファイル・手編集を拒否します。変更時は既知の生成物をCodex探索先の外へ退避して再生成し、原本と公開状態を変更しません。同期失敗は管理画面へ表示し、HTTP/MCPサービスを止めません。利用者が実際に選択したか、Codexの既存会話へ何が読み込まれたかは、この設定と生成物だけでは観測できません。
