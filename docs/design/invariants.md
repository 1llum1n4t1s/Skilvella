# 重要な不変条件

[DESIGN.md](../../DESIGN.md) から分割した詳細です。関連する流れは [data-flow.md](data-flow.md) を参照してください。

- 新規に見つかったスキルは、読み取りエラーがなければ公開で登録します（走査の `INSERT` だけが既定の公開状態を決め、`ON CONFLICT` の更新は公開状態を変えません。既存行の公開状態は利用者の選択として保持し、再スキャン・起動時・外部編集で自動公開しません）。読み取りエラー・不正frontmatterの新規行は未公開で、あとから直っても自動では公開しません。frontmatterの `name`・`description` が欠けている、マッピングでない、解析後の木の深さが64段（エイリアスは参照先の高さを足して数えます）を超える場合は、木を組み立てる前にパーサーのイベント列を数えて検査し、不正frontmatterの未公開のエラー行にします（深い入れ子でスタックあふれを起こしません。イベント列の取得は反復処理でスタックを使いません）。読めない相対パス（Windowsの末尾 `.`・空白など）のスキルも未公開のエラー行にし、非公開への切替は実パスを検査せず、DB上の行だけで行えます。未公開・不正frontmatter・消失・無効ソースのスキル本文はMCPへ返しません。公開設定は外部クライアントのネイティブ探索設定を変更しません。二重読み込みを避けるための標準探索先以外への原本配置は利用者が行います。反映にはCodexの再起動が必要です。既存会話のコンテキストは削除しません。
- 旧版の移行復旧でも、標準探索先・他の登録先との重複、リンク・特殊ファイル・Git worktree・外部共有参照などの安全性検査を維持し、元データと復旧記録を保護します。
- IDはソースエイリアスと、最初に登録したときの相対パスの綴りのハッシュから作り、絶対パスそのものは含めません。大文字小文字を区別しないファイルシステム（Windows・macOS）では、フォルダー名のASCIIの英字の大文字小文字だけの変更を同じスキルとして扱い（非ASCIIの文字の大文字小文字だけの変更は、別のスキルとして扱います）、既存行のIDを再利用して綴りだけを更新します（公開状態・タグ・履歴を引き継ぎます）。そのためIDは現在の綴りのハッシュとは限りません。Linuxは大文字小文字を区別するため、別のスキルとして扱います。ソース解除ではファイルと管理情報を削除せず、同じフォルダーの再登録で同じエイリアスを再利用して引き継ぎます。解除済みのエイリアスを別フォルダーへ付け替えません（場所の付け替え `relocate_source` は識別子を保つ別の操作です。詳細は [data-flow.md](data-flow.md)）。
- ソースの表示名はSQLiteの `settings` に `source_display_name:<alias>` として保存します。一覧ではソースと件数を読むクエリで表示名も取得し、未設定時はエイリアスを使います。Libraryで制御文字を拒否し、前後の空白を除去する前に100文字以内か検査します。空欄またはエイリアスと同じ名前なら設定を削除します。表示名の変更はID・パス・履歴・公開状態・MCP応答の識別子を変更しません。同名を許容し、名前を変えたソースには画面上でエイリアスを併記します。
- `SKILL.md` 発見後も走査を続け、親子を別ID・公開設定で扱います。親の参照取得は子の領域へ入りません。既知の子のマーカーが消失しても、その境界を保持します。
- シンボリックリンク・Windows reparse pointを拒否し、`.git`、`node_modules`、`target`、`.work` と `.skilvella-` で始まる一時ファイルを走査対象外にします。データ保存先とソースの包含・重複、およびソース同士の重複も拒否します。パスの再検査は行いますが、外部プロセスによる検査直後のファイル構造の差替えを完全には排除しません。
- 本文は最大2 MiB、参照は最大1 MiBのUTF-8テキストです。ファイルやスクリプトの実行機能は提供しません。この原則のため、Claude Codeの入口へ本文を埋め込むときも、`!` による動的コマンドを含む本文は埋め込みません（入口に置くとClaude Codeが許可確認なしに実行するため。[client-sync.md](client-sync.md)）。非公開化などで除去した旧入口は退避フォルダー（`~/.claude/skilvella-retired/<uuid>`）へ移り、次の同期まで本文入りの写しが一時的に残ります（探索先ではありません）。
- HTTPはIPv4 loopbackへbindし、Hostと、存在する場合のOriginを検査します。管理フォームのPOSTには起動ごとのCSRFトークンを要求します。`Referrer-Policy: same-origin` は通常の同一サイト内フォームPOSTのOriginを保持するために必要です。`no-referrer` ではOriginがnullとなり、境界検査に拒否されます。同一PCの利用者・プロセスを信頼する境界であり、複数利用者向けの認証・遠隔公開は提供しません。
- Askamaのエスケープ、Comrakの安全設定とタグの無害化、CSPでプレビューのHTML・画像読込み・リンク操作・スクリプトを抑制します。
