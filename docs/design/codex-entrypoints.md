# Codexの呼び出し入口

[DESIGN.md](../../DESIGN.md) から分割した詳細です。Codex以外を含む同期先クライアントごとの配置は [client-sync.md](client-sync.md) にあります。

一覧の個別モード保存はタブ内のsessionStorageに操作IDを記録する。HTTP切断後も保存・同期タスクを完了させ、プロセス共有の上限付き記録で状態を照合する。未知IDの取消確定はCSRF付きPOSTで行い、遅着POSTを拒否する。画面復元中は設定表示を隠し、完了後に再取得する。bfcache復帰でも設定を更新し、本文エディターは保持する。未受付・期限切れ・プロセス終了による記録消失では過去の保存成否を断定せず、最新状態と確認不能を通知する。

Codex連携は明示的に有効化します。各スキルの自動選択と候補表示をSQLiteの設定として保持し、既定は両方無効の「検索のみ」です。管理画面はフォーム入力と一覧の選択状態に同じ3モードの対応表を使います。Codexが自動選択用メタデータを読みながら候補だけを隠す独立ポリシーを提供しないため、自動選択は候補表示と併用します。MCP公開判定を通るスキルのうち候補表示対象だけに、原本の代わりにMCPの本文取得へ誘導する短い `SKILL.md` を生成します。検索用の `skilvella-search` は常に明示呼び出し専用で生成します。

有効なソースを1つでも開けないときは、そのソースを削除済みと判断せず（切断中のドライブで入口を退避しないため）、同期全体を意図的に停止して `Skill source unavailable` を同期エラーに保存します。この停止は変えず、管理画面で解消できるようにします（移動なら場所の変更、不要なら管理から外す。[データフローと永続化](data-flow.md) を参照）。

同期はサービス内の独立タスクで起動時・定期確認時に実行し、更新操作ではレスポンスを返す前に同期状態を確定します。同期ファイルI/OとSQLiteはLibraryの操作ロック内に置き、HTTPハンドラーからは `AppState::run_mut`、同期タスクからは `spawn_blocking` を通します。読み取りは `AppState::run` を使い、同期を誘発しません。正常終了・サービス再起動では同期中の処理の完了を待ちます。OS固有の定期タスクや外部ランタイムを必要としません。

個別スキルと検索用の入口には共通のMCP取得案内を付けます。直接接続では公開された名前空間のツールを使い、Toolport経由では `toolport_search_tools` で必要な操作を発見し、返却された正確な名前と `arguments` を `toolport_call_tool` に渡します。初期ツール一覧に名前がないだけで未接続と判断せず、遅延公開された探索ツールも確認します。探索や実呼び出しが失敗した場合はエラーを報告し、ローカル原本で代替しません。案内の更新も既存の所有権・ハッシュ検査を通して同期します。

所有元・出力先・相対パスを確認できた既知のCodex入口は、手編集や消失後も原本の走査から除外し、旧索引行を不在扱いにします。中断記録では、退避済みの旧出力先を所有中とみなさず、新しい出力先はステージからの公開後と確認できる場合だけ同様に扱います。自動判定では、既知の入口が実在し、それ以外にスキルがない候補を飛ばして次の標準探索先または専用フォルダーを選びます。部分的な読み取り失敗・記録の破損・所有元の不一致で判断できないときは検出先を未確定とし、保存済みの自動登録先を維持します。未確定のまま手動設定から自動へ切り替えることもできません。入口と未知のスキルが混在する場合は通常の優先順位を保ち、所有記録のない同名フォルダーは除外しません。手編集・管理外ファイルの検出と同期時の重複禁止は引き続き同期側で行います。

所有記録の検証ができない状態では、出力予定先または記録から確認できた出力領域内の索引更新だけを保留します。その領域の既存行と管理情報を保持したままエラーとして扱い、生成入口を新しい原本として登録したり、不確かな内容をMCP公開したりしません。同じソース内の兄弟フォルダーなど、領域外は通常どおり走査できます。
