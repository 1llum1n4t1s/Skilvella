# 配布物の梱包と検証

[DESIGN.md](../../DESIGN.md) から分割した詳細です。更新の受け入れ側は [app-updates.md](app-updates.md) を参照してください。

`skilvella-release` は対象OS上で本体を梱包し、Cargoの版や渡されたソースコミットを `BUILD-INFO.txt` に記録します。`pack` は共通検証で読み出した実行ファイルが梱包元と一致してからアーカイブを保存します。`checksums` が両OSのアーカイブから `SHA256SUMS.txt` を生成し、公開前の `verify` はこの一覧と配布ツールのCargo版を使って、両アーカイブを同じ `verify_archive` で検証します。公開時と利用者の更新時で受け入れ条件を共通化することで、梱包形式の不一致をアップロード前に検出できます。本体が表示する版と署名状態は公開手順で別途確認します。

公開前の `release_update` は `release-update-test` 機能で有効にする統合テストです。起点（R2の `portable/<版>/` から取得してチェックサムを照合した前の公開版、またはチェックサムを添えたローカルのフォルダー。版は `BUILD-INFO.txt`）を、専用のホームとデータを使って通常配置で起動します。候補の `latest.json`・アーカイブ・チェックサムは、偽のR2ホスト（`skilvella.kagayoi.com`）を装うループバックのHTTPSプロキシが配信し、プロキシと証明書の設定はテストの子プロセス内に限ります。設定画面と同じ更新確認・適用のHTTP経路を使い、旧プロセスの正常終了、置換後の実行ファイルと候補版の一致、別プロセスへの再起動、同じURLでの管理画面と設定画面の復帰、新しい版の表示を確認します。手順は [配布物の作成と検証](../DEVELOPMENT.md#配布物の作成と検証) を参照してください。
