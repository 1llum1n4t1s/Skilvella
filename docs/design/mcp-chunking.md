# MCPの分割取得

[DESIGN.md](../../DESIGN.md) から分割した詳細です。

`src/mcp.rs` は本文と参照ファイルをUTF-8境界で約8 KiBずつ返し、`load_skill` の本文とファイル一覧の続きを `next` で示します。ファイル一覧は通常100件・パス合計8 KiBまでとし、8 KiBを超えるパスは完全な1件として単独で返すため応答は上限を超えます。`read_skill_file` は行範囲をバイト単位でも分割します。バイト継続には `expected_revision` を必須とし、リビジョンを渡した継続要求では変更の混在を拒否します。本文取得では本文のSHA-256と順序付きの参照パス一覧、参照取得では本文のSHA-256と参照ファイル全体からリビジョンを計算します。いずれも分割位置によらず、同じ入力から同じ値を返します。リビジョンを省略した独立の行範囲要求間では版の一致を保証しません。必須としているのは、分割取得の途中で版が入れ替わった本文を連結させないためで、省略した継続を最新版で黙って補う経路は設けません。代わりに `read_skill_file` は続きの引数一式を `next`（`expected_revision` を含む）で返し、欠落時のエラー文も正しい呼び方を示します。MCPの `id` は、実IDに一致しなければ公開中のスキル名との完全一致を調べ、1件だけなら実IDへ解決します（解決後は通常のIDと同じ公開・パス検査を通ります）。同名が複数あれば解決せず候補のIDを返し、名前を選んで読む経路は作りません。参照は公開・パス境界と読取前後の再検査を通します。クライアントの連結・継続手順は [MCP接続](../../README.md#mcp-connection) を参照してください。

管理画面の詳細取得とMCPの本文・参照取得は、Library内の共通処理で公開条件に応じた実ファイルの検査を行います。管理画面では参照ファイル一覧と編集履歴を読み、MCPの本文取得では参照ファイル一覧だけを読みます。参照取得ではどちらも読まず、指定ファイルのパス・子スキル境界と読取前後の公開状態・本文リビジョンを検査します。応答に不要な一覧走査と履歴読取りを省きながら、公開判定・変更検出・親子境界の検査を共通の経路に保ちます。
