# ライブラリの取得元選択

[DESIGN.md](../../DESIGN.md) から分割した詳細です。

管理画面の通常一覧は `status=present` で不在の索引を除外し、サイドバーと一覧の件数も現在存在するファイルを数えます。旧パスの索引・設定・履歴は削除せず、`status=missing` または `status=all` で確認できます。Libraryの既定検索は不在行も対象とし、MCP検索は公開可能な行だけを返します。不在登録の一括削除はLibraryの操作ロック下で通常検索と同じ条件判定・並び順を使って全件のIDを一度に確定し、画面の対象件数との一致、ソースへの接続、各パスの不在を再確認します。全件を確認してから索引・履歴・Codex設定を1トランザクションで削除し、FTSを更新します。HTTPはCSRFと確認ダイアログを通り、`AppState::run_mut` で入口同期を待ちます。実ファイルは変更しません。

管理画面はライブラリと管理中フォルダーを1画面に統合しています。以前は取得元の選択画面とフォルダー画面を分けていましたが、ライブラリの中身はフォルダーそのものなので、左側にフォルダー（とその中の取得元）のツリー、右側に一覧を置きます。初期表示から全フォルダーを横断して一覧し、`source=<alias>` でフォルダー全体、`repository_source`・`repository` で取得元に絞り込みます。旧 `/sources` のGETは同じ条件で `/` へ転送し、フォルダー操作のPOST（`/sources/add`・`/sources/name`・`/sources/remove`・`/sources/directory`・`/sources/location`）は経路を維持して結果をフォルダー表示へ戻します。取得元ごとの一括設定は絞り込みのない一覧の折りたたみ欄に置きます。読み取りエラーの案内は、取得元を集計するときに有効なソースのエラー行を数え、横断一覧へ誘導します。エラーが記録された不在行も集計に含めます。Library内でソース直下（またはソース自体）の `.git` の通常ディレクトリ・通常ファイルを検出し、Git設定の読取りやリンク先の走査は行いません。直下の子リポジトリを優先し、それ以外をソースごとの個人スキルとして集約します。子リポジトリがない場合に限り、ソース自体のGitリポジトリを1つの取得元として扱います。取得元はソースaliasと相対ディレクトリで識別し、空ディレクトリは個人スキル、`.` はソース自体のリポジトリです。管理画面専用の取得元条件は、MCPと共通の検索条件に加えてページ分割前に適用します。

取得元の検出結果はソースaliasと実パスをキーにsettingsへ保存し、起動時の復旧後と走査時の操作ロック内で更新します。切断やマーカーの消失時も検出済みの取得元を保持し、初回から確認不能の場合は個人スキルと断定せずソース単位の未確認カードを表示し、その取得元の選択時だけエラーにします。正常なソースの検索・詳細は利用できます。マーカー消失後の保存済み取得元は索引のスキル行が残る間だけ保持し、ソースの検査自体が失敗した場合は保存済みの分類をそのまま使います。GETでもマーカーを再確認し、保存済みの取得元と統合しますが、検出結果をDBへ書き込みません。空の子リポジトリも直下のマーカーで認識します。カテゴリは既存の管理情報のままです。
