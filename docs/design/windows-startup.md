# Windowsの起動とサインイン登録

[DESIGN.md](../../DESIGN.md) から分割した詳細です。

本体はGUIサブシステムで動作し、エクスプローラーから起動したときにコンソールを新設しません。標準出力と標準エラーのハンドルが両方とも無効な場合だけ親コンソールへの接続を試みるため、呼び出し元の出力リダイレクトを保ちます。

引数なしの通常起動では、ポートの確保とライブラリの初期化後に、現在のユーザーの `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` に `Skilvella` の値を登録します。登録値は引用符で囲んだ実行ファイルの絶対パスと `--no-autostart` からなる `REG_SZ` です。既存値は保持し、登録に失敗しても標準エラーに出力してサービスを起動します。

Toolportの版別キャッシュはサインイン登録から除外します。更新処理と同じ配置判定を使い、実行ファイルが `versions/<版>/` 配下にあり、`versions` の親に `Skilvella-Latest.ps1` がある場合を対象とします。これにより、サインイン起動が更新前の版を参照し続けるのを防ぎます。

引数なしの通常起動と、`--no-autostart` だけを付けた起動（サインイン登録からの起動）では、同じくポートの確保とライブラリの初期化後に、現在のユーザーのスタートメニューのプログラムフォルダー（`FOLDERID_Programs`）へ `Skilvella.lnk` を作成します。リンク先は実行ファイルの絶対パス、作業ディレクトリはそのフォルダーです。ショートカットはアイコンを個別に持たず、`build.rs` が本体へ埋め込んだアプリアイコンを表示します。同名の項目が既にあれば種類を問わず利用者の設定として保持し、上書きしません。Toolportの版別キャッシュはサインイン登録と同じ判定で除外します。作成に失敗しても標準エラーに出力してサービスを起動します。ほかの引数を伴う起動では、サインイン登録もショートカット作成も行いません。

`windows-installer` 機能付きのビルドでは、通常起動時のRun登録とショートカット作成をどちらも行いません。ショートカットはVelopackがインストール時に作ります（同名の `Skilvella.lnk` があれば上書きするため、ZIP版のショートカットもSetup版を指すようになります）。Run登録は、Velopackのインストール直後の高速フックで `take_over_at_logon` が行います。値が無ければSetup版（`current\skilvella.exe --no-autostart`）を登録し、値が `skilvella.exe` を指す別配置（ZIP版・旧Setup版など）ならSetup版へ置き換え、それ以外のプログラムを指す値は保持します。ZIP版の登録を残すと、サインイン時に旧版が先にポートを取り、Setup版が起動できなくなるためです。利用者が無効にした自動起動は `StartupApproved` に値名で記録されるため、置き換えても無効のまま保たれます。アンインストール直前の高速フックは、Setup版自身を指す値だけを削除します。フックの失敗はインストール・アンインストールを止めません。ポートを確保できなかった場合は、コンソールを持たないため、別のSkilvella（ZIP版など）の終了を案内するメッセージボックスを表示して終了します。更新ヘルパーとしての起動分岐にも入りません。ZIP版の更新ヘルパー経路（`check`・`prepare_install`）は使わず、Velopackによる自動更新に置き換わります（[Setup版（Velopack）の自動更新](velopack-updates.md)）。
