# Setup版（Velopack）の自動更新

[DESIGN.md](../../DESIGN.md) から分割した詳細です。ZIP版・macOS版の更新は [app-updates.md](app-updates.md) を参照してください。

`src/update/auto.rs` が担当します。設定・間引きの判定は全ビルド共通の純粋な処理で、Velopackを呼ぶ部分だけを `windows-installer` 機能付きのWindowsビルドに限定します。

- **更新元**: 本番はVelopackの `HttpSource` で `https://skilvella.kagayoi.com`（Cloudflare R2、他アプリと同じ `<app>.kagayoi.com` 方式）。`releases.win.json` と `*-full.nupkg` を読みます。生成は `update_source` の1か所に閉じ、公開先を変える場合はこの関数だけを差し替えます。`update-feed-test` 機能付きのビルドに限り、環境変数 `SKILVELLA_UPDATE_FEED_DIR` のローカルフォルダーを更新元にできます。隔離したE2E検証専用で、公開用ビルドには含めません。
- **起動時と常駐中の確認**: ポート確保・Library初期化の後、起動ごとに1回だけ専用のstd::threadを開始します（サービス再起動のループ内では開始しません）。Tokioの2ワーカーは塞ぎません。スレッドは1時間ごとに「ONで、前回の確認から24時間以上たっているか」を見直し、時期なら確認して新版があれば無言で取得だけ行います。適用は次回起動時に `VelopackApp::run()` の自動適用（同じ引数で再起動）に任せるため、取得直後には再起動しません。`wait_exit_then_apply_updates` は終了待ちが60秒のため、常駐中の自動取得には使いません。
- **間引き**: 確認に成功（更新なしを含む）した時刻を記録し、24時間未満ではネットワークに出ません。取得に失敗した場合は時刻を記録せず、次の見直し（最長1時間後）で再試行します。失敗は標準エラーに残し、現行版で動き続けます。前回時刻が未来の場合は確認の時期とみなします。
- **設定の保存先**: ON/OFF（`auto_update`、未設定はON）と最終確認時刻（`last_checked_at`、UNIX秒）は、データフォルダー（`--data-dir`）直下の `app-update.json` に保存します。Libraryのsettingsテーブルは使いません（更新はLibraryや利用者スキルを変更しないため）。Velopackの導入先 `current\` 配下は更新で入れ替わるため使いません。一時ファイルを経由する原子的置換で保存し、2つの書込み元（設定画面と背景スレッド）は1つのロックで直列化します。読めない・壊れている・型が違う項目は項目ごとに既定値で動きます。
- **設定画面**: Setup版だけ「起動時に自動で更新する」を表示し、CSRF付きの `/settings/updates/auto` へ通常のフォームPOSTで保存します。ZIP版・macOS版ではこの経路は404です。手動の「更新を確認」は間引きを無視してVelopackで確認します。確認時刻は記録しません（新版を見つけても取得していない段階で記録すると、次の自動取得が24時間止まるため）。「更新をインストール」は取得後に `wait_exit_then_apply_updates` へ現在の起動引数を渡し、HTTP応答を返してから通常の終了処理へ進みます（Velopackが終了後に適用して同じ引数で再起動します）。`apply_updates_and_restart` は関数内で `exit` するため応答を返せず、使いません。
- **排他**: 確認・取得・適用はプロセス内の1つのロックで直列化し、重なった場合は「別の更新操作が進行中」を返します。
