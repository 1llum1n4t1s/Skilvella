# データフローと永続化

[DESIGN.md](../../DESIGN.md) から分割した詳細です。守るべき条件は [invariants.md](invariants.md) にあります。

1. 起動時はデータに触れる前にポートを確保します。`Library::open_for_user` が現在のホームと `CODEX_HOME` の標準探索先を記録して未完了の移行を復旧し、その後 `initialize_directory` が保存済み設定とホーム配下の候補から管理フォルダーを決め、走査します。`Library::open` 単独では利用者スキルを自動探索しません。
2. 走査は登録ソース配下の `SKILL.md` を再帰収集し、Saphyrでfrontmatterを解析してSQLiteの索引を更新します（解析前に `saphyr-parser` のイベント列で入れ子の深さを検査します）。ファイル監視と管理画面の再スキャンはこの走査経路に合流します。
3. 検索は索引を使い、3文字以上の語をFTS5 trigramで絞った後、Unicode小文字化したリテラル部分一致で全語のAND条件を確認します。短い語も部分一致で扱い、名前・タグの一致を優先します。意味検索や埋め込みモデルは使いません。
4. 本文編集・復元は期待リビジョンと実ファイルのSHA-256を照合し、変更前の本文を履歴へ保存してからファイルを置き換え、索引を更新します。本文・単一スキルのメタデータ更新では、同じDBトランザクション内で対象IDのFTS行だけを置き換えます。走査・移行復旧・一括操作はFTS全体を再構築し、いずれもRustの小文字化とタグの空白結合を共用します。競合時はWeb応答に下書きを保持します。
5. MCP検索は公開可能な索引行に限定します。本文取得は実ファイルを再検査し、参照取得は前後で公開状態・本文リビジョン・子スキル境界を確認します。監視の反映だけに公開可否を委ねません。
6. フォルダーの登録・参照先変更はファイルを移動せず、新規に見つかったスキルのうち読み取れるものを公開で、読み取りエラーのものを未公開で登録します。画面からの追加（`Library::add_folder`）は識別子を入力させず、フォルダー名からASCIIの識別子を自動採番し（日本語名などは `folder`、重複は `-2` 以降）、フォルダー名を表示名に保存します。解除済みの行と同じフォルダー（正規化したパスで比較）なら、その識別子を再利用して管理情報を引き継ぎます。識別子を明示する `add_source` は互換・テスト用で、別フォルダーへの識別子の付け替えは拒否します。重複・親子関係・データフォルダーとの重なりは `FolderError` で返し、画面が対象のフォルダー名を示す翻訳済みの文言にします。フォルダー選択ダイアログ（`POST /dialog/folder`）はCSRFを検査し、同時に1つだけ開き、選んだパスを返すだけです。ファイルを移動する画面・HTTP操作・新規移行開始処理は提供しません。Codexの設定ファイルは変更しません。

フォルダーを別の場所へ移した後の付け替え（`Library::relocate_source`）と、移動・消失・切断を示す不在の印は [source-relocation.md](source-relocation.md) にあります。取得元ごとの一括公開と一覧の公開状態の更新は [bulk-publish.md](bulk-publish.md) にあります。

登録フォルダーのファイルが本文・参照の正本です。`library.sqlite3` の `sources`、`skills`、`history`、`settings` は登録先、タグ・カテゴリ・公開状態、履歴、管理フォルダー設定を保持し、`skill_fts` は検索索引です。DBにはファイルから再生成できない管理情報もあるため、使い捨てキャッシュとして扱えません。

SQLiteはWALと接続ごとの10秒のbusy timeoutを使い、複製したLibrary間では書込Mutexを共有します。さらにデータフォルダーの `library.write.lock` にOSのファイルロックを取り、独立したLibrary・別プロセスの書込みと起動時復旧も直列化します。同期I/Oを非同期ランタイムから分離し、移行途中の状態へ別の書込みが割り込むことを防ぎます。本文ファイルとDBは単一トランザクションにはならず、索引更新の失敗はファイルからの再スキャンで回復します。別プロセスから同じデータを同時編集する運用は対象外です。

旧版の `settings.pending_migration` に残った移行記録だけは、起動時に操作ロックとフォルダー同一性検査を通して復旧します。元だけが残っていれば記録を解消し、移動先だけが残っていれば登録先の更新・再走査・有効スキルの公開・記録の削除を一つのDBトランザクションで確定します。両方存在・両方不在・ディレクトリ差替えなど自動判断できない状態では、記録を残して起動を止めます。再スキャンは未完了の移行を復旧しません。
