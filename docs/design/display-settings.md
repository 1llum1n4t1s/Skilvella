# 表示設定

[DESIGN.md](../../DESIGN.md) から分割した詳細です。

`Locale` はリクエストごとに言語を決めます。明示選択は接続ポートを名前に含むCookieから読み、自動選択では `Accept-Language` の対応言語から優先度が最も高いものを選びます。ヘッダーがなければ日本語、ヘッダーがあって使える候補がなければ英語です。`POST /settings/language` はCSRFトークンと言語コードを検証し、Cookieを設定して設定画面へリダイレクトします。旧版のlocalStorageからの移行は、有効な言語Cookieがない場合に限り、GETで開いた画面のJavaScriptが行います。GETに限定することで、POSTの再送や下書き画面の再読み込みを避けます。

Askamaが同梱辞書を使って最初のHTMLから選択言語で描画します。翻訳キーには日本語の原文を使い、辞書に項目がなければ原文を表示します。全辞書のキー・プレースホルダーの一致と、テンプレートが直接参照する原文の訳の有無はテストで検証します。JavaScriptへは選択件数や保存結果など、動的な操作に使う文言だけを渡します。フォーム操作後の通知は、リダイレクトで渡した通知IDと必要な件数から遷移先の言語で描画します。翻訳の対象は管理画面の文言で、スキルの内容・パス・技術的なエラー詳細は原文を保持します。

管理画面の外で人が読む文言（`--help`・起動時の停止案内・コマンドラインのエラー・常駐中の診断出力、トレイとメニューバーのメニュー、Setup版のポート使用中のメッセージボックス）は `src/locale.rs` が同じ9言語で出します。言語はブラウザーがないため、環境変数 `SKILVELLA_LANGUAGE`、`LC_ALL`、`LC_MESSAGES`、`LANG`（空・`C`・`POSIX` は除く）、OSの表示言語（Windowsは `GetUserDefaultUILanguage`、macOSは `AppleLanguages` の先頭）の順に決め、対応外・判定不能なら英語です。言語タグは `zh-Hans`・`zh-CN`・`zh-SG` を簡体字、`zh-Hant`・`zh-TW`・`zh-HK`・`zh-MO` を繁体字、`pt` 系を `pt-BR` に寄せ、それ以外は主言語で照合します。辞書は管理画面と同じく日本語の原文をキーにし（日本語は原文そのもの）、`src/locales/<タグ>.json` に置きます。判定は1プロセスで1回だけ行い（macOSは子プロセスを使うため）、辞書にないキーは原文を表示します。起動時の `Browser:`・`MCP:`・`Data:` の行はテストや配布検証が読み取る固定形式のため訳しません。キー・プレースホルダーの一致と、コードが参照するキーの辞書の有無（参照されない古いキーを含む）は `tests/localization.rs` で検証します。

AIが読む文言はアプリ内で訳し分けず英語に統一します。対象はMCPのツール名・説明・入力スキーマの説明・サーバーの `instructions`、MCPがAIへ返すエラー文です。MCPの契約（ツール名・引数・応答の形）は言語で変わりません。更新ヘルパーの `update.log` は機械が解析する診断ログのため、英語のまま残します。READMEは英語の `README.md` を正本に、`README.ja.md` ほか7言語版を置きます。

テーマはオリジンごとのlocalStorageに保存し、`static/theme.js` がCSSの読み込み前に適用します。自動配色にはCSSのメディアクエリを使います。言語とテーマはブラウザー内の設定で、LibraryのDBと独立しています。操作は [表示設定](../../README.md#display-settings) を参照してください。

管理画面の設定フォーム（同期先、各スキルの使い方・管理情報、フォルダーの表示名、起動時の自動更新）は `data-save-on-change` を持ち、`static/app.js` が、チェック・選択の切り替え時と文字入力の確定（Enter）時に `requestSubmit()` で送ります。保存ボタンは `<noscript>` 内にだけ置き、JavaScriptなしでも従来どおりPOSTで保存できます。サーバー側の保存経路は変えず、CSRF・検証・競合検出は通常のフォーム送信と同じです。スキル本文の保存と、追加・スキャン・削除などの操作ボタンは対象外で、明示的な送信のままにします。
