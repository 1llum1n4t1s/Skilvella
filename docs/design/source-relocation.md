# フォルダーの場所変更と不在検出

[data-flow.md](data-flow.md) から分割した詳細です。

## 場所の付け替え

利用者がフォルダーを別の場所へ移した後は、`Library::relocate_source`（`POST /sources/location`、CSRF必須）で、管理中のフォルダーの登録の場所だけを付け替えます。ファイルは動かしません。

- 検査は登録と共通の `checked_source_root`（絶対パス・リンク拒否・存在・ディレクトリ・UTF-8・データフォルダーとの重なり）を通します。変更先が別の有効なフォルダーと同じ場合は `FolderError::RelocationTargetManaged`（先にそのフォルダーを管理から外す）、親子関係なら `FolderError::Overlaps` で拒否します。
- 操作ロックと移行の未完了検査を通り、識別子を保ったまま `sources.path` だけを更新して再走査します。相対パスが同じスキルは同じIDのまま公開状態・使い方（`codex_policy:<id>`）・履歴・表示名を引き継ぎます（変更先で相対パスが変わったスキルは別IDになります）。
- 既定フォルダー（`directory.source_alias`）なら、既定フォルダーの設定も手動指定（`custom`）の新しい場所へ揃えます。
- 既存の「参照するフォルダーを変更」（`/sources/directory`）は別のフォルダーへ切り替える操作で、識別子が変わるため、移動への追従には使いません。
- HTTPは `AppState::run_mut` で入口同期を待ち、成功時に `state.rescan` を通知して、監視先を新しい場所へ張り替えます。

## 不在の印

フォルダー自体を開けなかったこと（移動・消失・切断）は、操作ロック内の走査と入口同期（`export_codex` が有効なソースを開く検査）だけが判定し、設定の `source_unavailable:<alias>` に印として保存します。

- 走査は失敗したときだけ `read_dir` で確かめます。同期は全ソースを確認して印を確定してから、従来どおり最初の失敗で止めます。
- 値が変わるときだけ書き、同期で読めたソースの印は次の再スキャンを待たずに外します。
- ファイル監視は登録フォルダー自体の改名・移動を検知しない場合があるため、再スキャンを押さなくても定期同期で印が付きます。
- 登録と場所の変更の重複・親子の判定は共通の `source_conflict` / `canonical_stored` を使います。同期エラーに出すパスは `\\?\` 接頭辞を外した表記です。
- サイドバーの警告バッジ、フォルダー画面の警告と「フォルダーの場所を変更」（不在時は開いた状態）、同期停止の警告（一覧・設定・詳細の3か所）の対象フォルダーへのリンクは、この印を読むだけで、描画のたびにファイルシステムを調べません。同期エラーの文字列は解析しません。
- 管理から外すと印も削除します。
