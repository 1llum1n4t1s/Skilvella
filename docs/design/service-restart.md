# サービスの再起動と終了

[DESIGN.md](../../DESIGN.md) から分割した詳細です。

WindowsとmacOSでは、デスクトップメニューからプロセス内のチャネルでサービス再起動・終了を要求します。AppKitの要件に合わせ、OSイベント処理はメインスレッド、HTTPはTokioのワーカースレッドで動かします。再起動・終了のHTTPエンドポイントは設けません。アイコン作成に失敗してもHTTPは継続し、サービス終了時は共有停止フラグでアイコン側も終了します。`--no-tray` とLinuxではHTTP/MCPのみを動かします。

再起動は重複要求をまとめ、MCP接続をキャンセルして処理中のHTTP操作を待ちます。操作ロックを共有する同じLibraryを使い、CSRFトークン・ルーター・ファイル監視を作り直します。同じTokio listenerを共有し、Axumのaccept処理がキャンセルされるとMutexが解放されるため、同じポートで待受を再開できます。ソケットの複製を避けることで、Windowsで複製ハンドルが更新ヘルパーや再起動先に継承され、新版のbindを妨げる問題を防ぎます。
