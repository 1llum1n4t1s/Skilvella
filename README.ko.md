# Skilvella

[日本語](README.ja.md) | [English](README.md) | [简体中文](README.zh-CN.md) | [繁體中文](README.zh-TW.md) | **한국어** | [Español](README.es.md) | [Français](README.fr.md) | [Deutsch](README.de.md) | [Português (Brasil)](README.pt-BR.md)

수많은 `SKILL.md` 파일을 브라우저에서 정리하고, 필요한 스킬만 MCP로 불러오는 로컬 앱입니다. 스킬이 아무리 많아도 MCP 도구는 세 개만 제공합니다.

- 이름, 설명, 본문, 태그를 키워드로 검색하며, 일본어 부분 문자열 일치도 지원합니다.
- 폴더 등록, 스킬 생성, 본문 편집, 태그와 카테고리, 일괄 작업, 스킬별 MCP 공개 전환을 제공합니다.
- 편집할 때마다 이력을 저장하고 복원할 수 있으며, 외부 편집과의 충돌 감지, 이름 중복·구문 오류·파일 누락 검사를 지원합니다.
- Windows / macOS / Linux를 지원합니다. 같은 PC의 브라우저에서 사용합니다.

## 시작하기

Windows에서는 [SkilvellaApp-win-Setup.exe](https://skilvella.kagayoi.com/SkilvellaApp-win-Setup.exe)를 실행한 뒤 시작 메뉴에서 "Skilvella"를 실행하세요. 설치 프로그램(Setup) 버전은 설치할 때 현재 사용자가 로그인하면 시작되도록 자신을 등록합니다. 기존 독립 실행형(ZIP) 버전에서 전환할 때는 먼저 작업 표시줄 트레이 아이콘에서 이전 버전을 종료하세요(이전 버전이 실행 중이면 기본 포트(7465)를 사용할 수 없으므로, 설치 프로그램(Setup) 버전은 그 내용을 안내하는 메시지를 표시하고 시작하지 않습니다). ZIP 버전의 로그인 시 자동 시작 등록은 설치할 때 설치 프로그램(Setup) 버전으로 자동 전환되며, 시작 메뉴의 "Skilvella" 바로 가기도 설치 프로그램(Setup) 버전을 가리키게 됩니다. 자동 시작을 꺼 두었다면 꺼진 상태로 유지됩니다. 제거할 때는 설치 프로그램(Setup) 버전을 가리키는 자동 시작 등록도 함께 삭제됩니다. 이전 버전의 폴더는 자동으로 삭제되지 않으므로 필요 없으면 직접 삭제하세요. 자동 업데이트 기능이 없는 이전 설치 프로그램(Setup) 버전(1.1.4~1.1.6)을 사용 중이라면 새 Setup으로 한 번 다시 설치하세요. 표준 데이터 폴더 `%LOCALAPPDATA%\Skilvella`는 공유되며 제거 후에도 남습니다. 설치 프로그램 버전은 자동으로 업데이트됩니다([앱 업데이트](#app-updates)).

ZIP 버전이나 macOS 버전을 사용하려면 해당하는 패키지([Windows x64](https://skilvella.kagayoi.com/portable/Skilvella-windows-x86_64.zip) 또는 [Mac Apple Silicon](https://skilvella.kagayoi.com/portable/Skilvella-macos-aarch64.tar.gz), skilvella.kagayoi.com에서 제공)를 내려받아 압축을 풀어 주세요. 1.1.8 이하의 ZIP 버전과 macOS 버전은 GitHub에서 업데이트를 확인했으며 이 방식은 더 이상 사용되지 않으므로, 해당 버전을 사용 중이라면 새 패키지를 한 번 직접 설치해 주세요.

- Windows x64: `Skilvella-windows-x86_64.zip`을 계속 사용할 폴더에 압축 해제한 뒤 `skilvella.exe`를 실행하세요. 터미널을 열지 않고 작업 표시줄 트레이에서 실행되며, 처음 일반 실행할 때 현재 사용자의 시작 메뉴에 "Skilvella"가 추가됩니다.
- Mac Apple Silicon: `Skilvella-macos-aarch64.tar.gz`의 압축을 풀고 터미널에서 `./skilvella`를 실행하세요.
- 압축을 풀기 전에 패키지의 SHA-256을 [`SHA256SUMS.txt`](https://skilvella.kagayoi.com/portable/SHA256SUMS.txt)와 대조해 확인할 수 있습니다.

Linux나 소스에서 빌드하는 방법은 [개발 가이드](docs/DEVELOPMENT.md)를 참고하세요.

Skilvella는 Windows에서는 작업 표시줄 트레이에, Mac에서는 메뉴 막대에 아이콘을 표시합니다. 왼쪽 클릭하면 기본 브라우저에서 관리 화면이 열립니다. 오른쪽 클릭(Mac에서는 Control 클릭)하면 "관리 화면 열기", "업데이트 확인", "서비스 다시 시작", "종료"를 선택할 수 있습니다. Windows에서 아이콘이 보이지 않으면 트레이의 숨겨진 아이콘 영역도 확인하세요.

"서비스 다시 시작"은 같은 프로세스, 같은 URL에서 HTTP/MCP 서버와 파일 감시를 다시 시작합니다. 저장된 스킬과 설정은 유지됩니다. 다시 시작하는 동안 들어온 중복 요청은 하나로 합쳐지며, 다시 시작은 처리 중인 HTTP 작업이 끝나기를 기다립니다. MCP 연결은 끊어지므로 클라이언트에서 다시 연결하세요. 열려 있는 관리 화면은 새로 고침한 후에 사용하세요. "종료"는 서버와 아이콘을 모두 종료합니다.

관리 화면은 [http://127.0.0.1:7465/](http://127.0.0.1:7465/)에서 직접 열 수도 있습니다. MCP 엔드포인트는 `http://127.0.0.1:7465/mcp`입니다. 디스플레이가 없는 환경에서는 `--no-tray`를 지정하세요. Linux에서는 아이콘 없이 HTTP/MCP 서버로 실행됩니다.

Windows 독립 실행형 구성에서는 인수 없이 실행하면 현재 사용자가 로그인할 때 앱이 시작되도록 등록을 시도합니다. 이미 등록되어 있으면 다른 위치에서 실행 파일을 실행해도 등록된 경로는 바뀌지 않습니다. 자동 시작은 Windows "설정" → "앱" → "시작 프로그램"에서 켜고 끌 수 있습니다. 이번 실행에서만 등록을 건너뛰려면 `--no-autostart`를 지정하세요. Toolport 관리 하에서의 자동 시작은 Toolport 쪽에서 설정하세요.

실행 시에는 Rust, Node.js, Python, 외부 데이터베이스 서버가 필요하지 않습니다. 터미널에서 실행했다면 연결된 콘솔에서 `Ctrl+C`로 종료할 수도 있습니다.

## 라이브러리 관리

처음 실행하면 Skilvella가 관리 폴더를 자동으로 감지합니다. 기존의 `~/.agents/skills`, `$CODEX_HOME/skills`, `~/.codex/skills`를 이 순서로 확인하고, 하나도 없으면 데이터 폴더 옆에 `<데이터 폴더 이름>-skills`를 만듭니다. Skilvella가 생성한 Codex 호출 진입점만 들어 있는 후보는 건너뛰며, 진입점 자체는 관리 대상 스킬로 세지 않습니다. 이는 데이터 폴더에 해당 진입점의 소유 기록이 있을 때만 성립합니다. 데이터 폴더를 다시 만들거나 `--data-dir`로 다른 폴더를 지정하면, 이전에 생성되어 남아 있는 진입점이 일반 스킬로 등록됩니다. 이전에 출처가 등록되어 있었다면 그 구성이 우선되어 승계됩니다. 진입점의 소유 기록이나 후보를 읽는 데 문제가 생겨 자동 감지를 확정할 수 없으면 저장된 자동 등록 대상이 유지됩니다. 감지 상태는 라이브러리 왼쪽의 폴더 목록에서 확인하세요.

라이브러리는 하나의 화면으로, 왼쪽에 관리 폴더 목록, 오른쪽에 스킬 목록이 있습니다. "+ 폴더 추가"를 누르면 OS 표준 폴더 선택 창이 열리며, 선택한 폴더는 그대로 등록되고 스캔됩니다. 파일은 이동하지 않습니다. 이름을 입력할 필요는 없으며 폴더 이름이 표시 이름으로 사용됩니다(나중에 "표시 이름 변경"으로 바꿀 수 있습니다). SSH 세션처럼 대화상자를 열 수 없는 환경에서는 "경로를 입력하여 추가"에 절대 경로를 입력하세요.

왼쪽에서 폴더를 선택하면 위치, 개수, 표준 탐색 경로 경고가 "표시 이름 변경", "관리에서 제외"와 함께 표시됩니다. 기본 폴더는 "참조 폴더 변경"으로 참조할 폴더를 바꿀 수 있고, "찾아보기…"로 대화상자에서 선택할 수 있습니다. 이 설정은 재시작 후에도 유지되며, "관리에서 제외"해도 파일은 삭제되지 않습니다. 이미 관리 중인 폴더나 관리 중인 폴더와 상위·하위 관계에 있는 폴더를 선택하면 추가가 중단되고 겹치는 폴더의 이름이 표시됩니다. 폴더를 Skilvella 밖에서 옮기거나 삭제하면 사이드바와 해당 폴더 화면에 경고가 표시되고, 해결할 때까지 동기화가 멈춥니다. 옮겼다면 "폴더 위치 변경"을 열어 새 위치를 입력하거나 "찾아보기…"로 선택하세요. 등록된 위치만 바뀌며 파일은 이동하지 않고, 스킬 ID·공개 상태·사용 방식·변경 이력은 유지됩니다. 더 이상 필요 없다면 "관리에서 제외"를 선택하세요. 새 위치가 이미 다른 폴더로 관리 중이면 먼저 그 폴더를 관리에서 제외하세요.

추가, 자동 감지, 외부 편집으로 발견된 새 스킬은 읽을 수 있으면 **MCP 공개가 켜진 상태**로 등록됩니다. 읽기 오류가 있거나 frontmatter가 잘못된 스킬은 비공개로 유지되며, 고쳐도 자동으로 공개되지 않습니다. 기존 스킬의 공개 상태는 다시 스캔하거나 시작할 때 바뀌지 않습니다(비공개로 바꾼 스킬이 자동으로 공개되는 일은 없습니다). Windows와 macOS에서는 ASCII 대소문자만 다른 폴더 이름은 같은 스킬로 취급하며 공개 상태도 바뀌지 않습니다. 스킬을 공개하고 싶지 않다면 폴더를 추가한 뒤 목록의 "상태" 열에서 "비공개"를 선택하세요. 목록의 "상태" 열에서 "공개" 또는 "비공개"를 선택하면 즉시 저장됩니다. 개별 페이지나 목록의 일괄 작업으로도 전환할 수 있습니다. 공개로 전환할 때는 파일을 다시 확인하며, 누락되었거나 읽기 오류가 있거나 frontmatter가 잘못된 스킬은 공개되지 않고 선택이 되돌려지며 이유가 표시됩니다. 태그와 카테고리는 바뀌지 않습니다.

라이브러리는 처음부터 모든 폴더의 스킬을 한 목록에 보여 주며 그 자리에서 검색할 수 있습니다. 폴더 바로 아래에 `.git` 디렉터리나 파일이 있는 것은 해당 폴더 아래에 출처(저장소)로 중첩되어 표시되고, 나머지는 "개인 스킬"로 묶입니다. 바로 아래에 출처 저장소가 없는 폴더 자체가 Git 저장소이면 폴더 전체가 하나의 출처가 됩니다. 일반 목록에는 현재 존재하는 스킬이 표시됩니다. 이동 전의 등록처럼 오래된 등록은 유지되며, 상태 "찾을 수 없음" 또는 "전체"와 왼쪽의 "존재하지 않는 스킬 등록 정리"에서 확인할 수 있습니다. "찾을 수 없음" 목록의 "누락된 등록 일괄 삭제"는 검색 조건에 일치하는 모든 페이지의 등록 데이터, 설정, 이력을 삭제합니다. 이 작업은 취소할 수 없습니다. 실제 파일은 변경하지 않으며, 출처에 연결할 수 없거나 경로가 존재하면 전체 삭제를 중단합니다. 카테고리는 각 스킬의 관리 정보에서 편집할 수 있습니다.

Skilvella는 등록된 폴더의 `SKILL.md`를 **깊이 제한 없이 재귀적으로** 검색합니다. 스킬을 찾은 뒤에도 더 깊은 하위 디렉터리를 계속 스캔합니다. 상위·하위 스킬은 별도의 ID와 공개 설정으로 관리되며, 하위 스킬의 파일은 상위 스킬의 MCP 공개 범위에 포함되지 않습니다. 심볼릭 링크, Windows 정션, `.git`, `node_modules`, `target`, `.work`는 제외됩니다. 폴더 등록을 해제해도 원본 파일은 삭제되지 않습니다. 관리에서 제외했던 폴더를 다시 추가하면 이전 관리 데이터(공개 설정, 태그, 이력)가 복원됩니다. 이름이 같은 폴더끼리는 충돌하지 않습니다.

본문을 저장하면 등록된 위치의 실제 파일이 변경됩니다. 미리 보기는 HTML, 이미지 로딩, 링크 동작을 비활성화하며 스크립트를 실행하지 않습니다. 외부 편집기로 한 변경은 자동으로 감시됩니다. 반영되지 않으면 "다시 스캔"을 사용하세요.

읽기 오류가 있으면 라이브러리의 "읽기 오류 확인 및 수정" 또는 왼쪽의 "읽기 오류"에서 폴더 전체의 오류 목록을 여세요. 스킬 이름이나 경로를 열어 원인을 확인하고, 구문 오류는 본문을 수정한 뒤 저장하세요. 파일을 읽을 수 없으면 위치, 권한, 문자 인코딩을 확인한 후 다시 스캔하세요. 오류가 해결되면 알림은 사라집니다.

## 앱 업데이트

**설치 프로그램(Setup) 버전**: 자동 업데이트가 기본으로 켜져 있습니다. 시작할 때와 실행 중 24시간마다 새 버전을 확인하고, 있으면 다운로드합니다. 업데이트는 다음 시작 때 자동으로 적용되며 같은 설정으로 다시 실행됩니다. 이전 확인으로부터 24시간 이내에는 연결하지 않습니다. 확인이나 다운로드에 실패하면 현재 버전을 계속 실행합니다. "설정"의 "앱 업데이트"에 있는 "시작할 때 자동으로 업데이트"에서 끌 수 있습니다(설정은 `%LOCALAPPDATA%\Skilvella` 같은 데이터 폴더의 `app-update.json`에 저장되며 스킬 라이브러리는 바뀌지 않습니다). "업데이트 확인"은 24시간 간격과 관계없이 확인하고, "업데이트 설치"는 업데이트를 다운로드한 뒤 즉시 다시 시작합니다. 업데이트 정보는 `skilvella.kagayoi.com`에서 가져옵니다.

다음은 독립 실행형(ZIP) 버전과 Mac에 해당합니다.

"설정"의 업데이트 영역이나 트레이 메뉴의 "업데이트 확인"에서 skilvella.kagayoi.com의 최신 안정 릴리스를 확인할 수 있습니다. "업데이트 설치"를 선택하면 Windows x64 / Mac Apple Silicon용 패키지와 `SHA256SUMS.txt`를 HTTPS로 내려받아 SHA-256을 검증한 뒤 적용합니다. 이를 위해서는 OS에 포함된 `curl`과 실행 파일 위치에 대한 쓰기 권한이 필요합니다. Linux나 다른 CPU에서는 앱 내 업데이트를 지원하지 않습니다.

업데이트는 처리 중인 HTTP 작업이 끝나기를 기다린 뒤 종료하고, 같은 실행 인수와 작업 폴더로 다시 시작합니다. MCP 클라이언트를 다시 연결하세요. 패키지 검증에 실패하면 현재 버전이 유지됩니다. 업데이트를 적용한 뒤 새 프로세스를 시작할 수 없으면 이전 실행 파일이나 Toolport 참조 대상을 복원하려고 시도합니다. 업데이트를 시작한 설정 페이지는 새 버전이 응답하면 자동으로 새로 고쳐집니다. 앱이 다시 시작되기 전에 이미 열려 있던 오래된 설정 페이지에서 업데이트 작업을 하면 페이지를 새로 고치라는 안내가 표시됩니다.

업데이트 전 실행 파일과 같은 위치에 `.skilvella-update-*` 폴더가 만들어지며 `update.log`가 보관됩니다. 일반 구성에서는 복구용 `previous-binary`도 이곳에 저장됩니다. 이 폴더는 만든 지 24시간이 넘고, 진행 중인 업데이트가 없으며, 업데이트 프로그램이 만든 파일로만 이루어진 경우에 한해 Skilvella가 시작할 때 자동으로 삭제합니다. 직접 삭제할 필요는 없으며, 삭제하려면 업데이트 도우미가 종료된 뒤에 하세요.

Toolport의 `Skilvella-Latest.ps1` 관리 하에서는 기존 버전이 유지되고, 새 버전의 폴더와 검증 정보가 추가되며, 런처의 참조 대상이 전환됩니다. 업데이트 도우미는 다시 시작된 앱이 종료될 때까지 실행되므로, 업데이트 폴더를 삭제하기 전에 Skilvella를 종료하세요.

Skilvella를 외부 프로세스 감시 도구로 실행한 경우에는 해당 도구에서 다시 시작해야 할 수 있습니다. Toolport 시작 잠금을 얻지 못하면 업데이트는 적용되지 않습니다. 시작되지 않으면 런처를 다시 실행하세요. 일본어 같은 비ASCII 문자가 포함된 Toolport 관리 위치에서는 앱 내 업데이트를 지원하지 않습니다. 일반 독립 실행형 구성은 이 제한의 대상이 아닙니다.

## MCP 연결

Streamable HTTP를 지원하는 클라이언트에 다음 URL을 등록하세요.

```text
http://127.0.0.1:7465/mcp
```

Toolport에서는 HTTP 서버로 등록하고 같은 URL을 지정하세요. Skilvella는 계속 실행해 두어야 합니다.

| 도구 | 용도 |
| --- | --- |
| `search_skills` | 공개된 스킬을 검색하여 요약과 ID를 가져옵니다 |
| `load_skill` | ID를 지정하여 `SKILL.md` 내용과 참조 파일 목록을 가져옵니다 |
| `read_skill_file` | 스킬 아래의 UTF-8 텍스트를 줄 단위로 가져옵니다 |

`load_skill`은 `next`가 null이 될 때까지 이어받기 인수를 계속 전달하고, 내용을 이어 붙인 뒤에 지시를 따르세요. 목록은 보통 페이지당 100개, 경로 합계 최대 8 KiB이지만, 경로 하나가 8 KiB를 넘으면 그 경로만 단독으로 반환되므로 응답이 커집니다. 스킬과 필요한 참조는 한 번에 하나씩 가져오세요. 참조는 `read_skill_file`로 필요한 줄 범위부터 끝까지 `next_text_offset`으로 가져오고, 줄이 더 필요할 때만 `next_start_line`을 사용하세요. 같은 줄 범위의 바이트 페이지는 그대로 이어 붙이고, 줄 범위 사이에서는 이어 붙일 때 줄바꿈을 넣습니다. `next_text_offset`으로 이어받을 때는 `start_line`과 `max_lines`를 유지하고, 다음 줄 범위로 넘어갈 때는 `start_line`을 `next_start_line`으로 설정하고 `text_offset`을 0으로 되돌립니다. 줄바꿈은 이전과 같이 정규화되며 끝의 줄바꿈은 제거됩니다. 이어받을 때는 반환된 `revision`을 `expected_revision`으로 지정하세요. 그 사이 파일이 바뀌었다면 처음부터 다시 가져오세요. `id`에는 `search_skills`가 반환한 스킬 ID를 지정합니다. 게시된 스킬 이름과 정확히 일치하고 유일하면 이름도 받으며, 여러 개와 일치하는 이름에는 후보 ID를 반환합니다. `read_skill_file`의 첫 호출에는 `id`와 `path`만 필요하며, 결과가 잘리면 `expected_revision`이 이미 들어 있는 `next` 객체를 그대로 전달해 이어 갑니다.

MCP는 읽기 전용입니다. 비공개 스킬, frontmatter가 잘못된 스킬, 누락된 스킬의 내용은 반환할 수 없습니다. 참조 파일을 실행하는 기능도 없습니다. 본문은 2 MiB, 참조 텍스트는 1 MiB로 제한됩니다.

MCP 공개만으로는 에이전트가 같은 스킬을 표준 방식으로 탐색하고 로드하는 것이 달라지지 않습니다. 중복 로드를 피하려면 에이전트의 표준 탐색 경로 밖에 스킬을 두고 그 위치를 라이브러리의 "+ 폴더 추가"로 등록하세요. Skilvella는 파일을 이동하지 않습니다. 기존 파일을 옮겨야 한다면 직접 옮긴 뒤 해당 폴더의 "폴더 위치 변경"에서 새 위치를 지정하세요. Codex의 설정 파일은 편집하지 않습니다. 표준 탐색 경로를 바꾼 뒤에는 Codex를 다시 시작하세요. 이미 대화에 로드된 내용은 제거되지 않습니다. 사용자 지정 탐색 설정과 다른 클라이언트는 별도로 확인하세요.

## 자동 선택과 명령 후보

먼저 [MCP 연결](#mcp-connection)을 사용하는 클라이언트에 Skilvella를 등록하고 동작을 확인하세요. "설정"의 "호출 진입점 동기화"에서 동기화 대상(Codex, Claude Code, Grok, Cursor, GitHub Copilot, Devin. 여러 개 선택 가능)을 체크하고 저장하면, Skilvella가 직접 각 클라이언트의 호출 진입점을 자동으로 동기화합니다. 이 PC에서 설정 폴더(`~/.cursor` 등)를 찾지 못한 클라이언트는 같은 양식의 "기타 클라이언트" 아래에 접어 둡니다. 켜져 있거나 동기화 오류가 있는 클라이언트는 항상 표시합니다. 상태 표에는 켜진 클라이언트와 동기화 오류가 있는 클라이언트만 표시합니다. 이전 버전에서 "Codex 연동"을 켜 두었다면 Codex가 선택된 상태로 승계됩니다. Windows, macOS, Linux에서 똑같이 동작하며 작업 스케줄러도, 별도의 상주 프로세스도 사용하지 않습니다. 동기화는 시작할 때, 관리 작업 후, 정기 점검 중에 실행되며, 서비스를 다시 시작한 뒤에도 설정이 유지됩니다.

| 동기화 대상 | 진입점 위치 | 탐색에 노출하는 방식 | 자동 선택 제어 |
| --- | --- | --- | --- |
| Codex | `~/.agents/skills/skilvella/<name>` | 실제 파일(Codex는 중첩 폴더를 탐색함) | `agents/openai.yaml` |
| Claude Code | `~/.claude/skilvella/skills/<name>` | `~/.claude/skills/<name>`으로의 링크(Windows는 정션, macOS와 Linux는 심볼릭 링크) | `disable-model-invocation` |
| Grok | `~/.grok/skills/skilvella/<name>` | 실제 파일(Grok은 중첩 폴더를 탐색함) | `disable-model-invocation` |
| Cursor | `~/.cursor/skills/skilvella/<name>` | 실제 파일(Cursor는 중첩 폴더를 탐색하지만 링크를 따라가지 않을 수 있음) | `disable-model-invocation` |
| GitHub Copilot | `~/.copilot/skilvella/skills/<name>` | `~/.copilot/skills/<name>`으로의 링크 | `disable-model-invocation` |
| Devin | `<Devin 설정>/skilvella/skills/<name>` | `<Devin 설정>/skills/<name>`으로의 링크 | `triggers: [user]` |

`<Devin 설정>`은 Windows에서 `%APPDATA%\devin`, macOS와 Linux에서 `~/.config/devin`입니다(`XDG_CONFIG_HOME`은 사용하지 않음). GitHub Copilot은 항상 `~/.copilot`을 사용하며 `COPILOT_HOME`을 따르지 않습니다.

Claude Code는 `~/.claude/skills` 바로 아래 한 단계만 탐색하므로, 진입점은 탐색 경로 밖에 두고 스킬마다 링크를 만듭니다. `~/.claude/skills`에 같은 이름의 기존 스킬이나 링크가 이미 있으면 덮어쓰지 않으며 해당 이름이 동기화 오류로 표시됩니다. 이전 버전의 안내에 따라 직접 만든 `~/.claude/skills/<name>`에서 `~/.agents/skills/skilvella/<name>`으로의 링크는 Claude Code 진입점을 가리키도록 다시 연결되어 관리 대상으로 승계되지만, 동기화 대상인 이름에 한합니다. 동기화 대상이 아닌 이름의 링크는 건드리지 않습니다(Codex를 끄면 그 참조 대상이 사라집니다). Claude Code의 동기화를 끄면 Skilvella가 만들었거나 승계한 링크만 제거됩니다. `~/.claude/skills` 자체를 관리 폴더로 등록했다면 동기화는 수행되지 않습니다.

Claude Code의 입구만 원본 `SKILL.md`의 frontmatter 키 일부도 이어받습니다. 따라서 `context: fork`(와 `agent: Explore` 같은 `agent`)를 가진 스킬을 입구를 통해 호출해도 서브에이전트로 fork 실행할 수 있습니다. 이어받는 키는 `context`(`fork`만), `agent`와 `background`(`context: fork`일 때만), `model`, `effort`(`low`, `medium`, `high`, `xhigh`, `max`), `argument-hint`, `paths`입니다. 값은 타입을 검사하며, 잘못된 키만 버립니다. 권한이나 세션 전체를 바꾸는 키(`allowed-tools`, `disallowed-tools`, `hooks`)는 이어받지 않으며, `shell`, `when_to_use`, `license` 등도 이어받지 않습니다. `disable-model-invocation`과 `user-invocable`은 Skilvella의 "사용 방식" 설정을 따릅니다. 다른 클라이언트의 입구는 그대로입니다. 호출에 인수가 있으면 입구는 읽어 들인 스킬의 입력으로 사용하도록 에이전트에게 알립니다. `context: fork`를 가진 스킬의 입구에 한해, MCP로 본문을 읽게 하는 안내 대신 원본 `SKILL.md`의 본문을 그대로 포함하고 `arguments`도 이어받습니다. 본문에 `!`로 시작하는 동적 명령이나 `CLAUDE_SKILL_DIR`가 있거나, 입구 전체가 2 MiB를 넘거나, 본문이 비어 있으면 포함하지 않고 기존 안내를 사용합니다. `~/.claude/skills`는 Cursor와 Grok도 읽으므로 포함된 본문은 이들에게도 보입니다.

GitHub Copilot(Copilot CLI는 `~/.copilot/skills/<name>/SKILL.md`만 찾음)과 Devin도 같은 링크 방식과 규칙을 따릅니다. 같은 이름의 기존 항목은 덮어쓰지 않고, Skilvella가 만든 링크만 제거하며, 링크 폴더가 관리 폴더와 겹치면 동기화하지 않습니다. 직접 만든 Codex 진입점 링크를 승계하는 것은 Claude Code뿐입니다. Copilot CLI가 `disable-model-invocation`을 따르는지와 Devin의 탐색 깊이는 확인되지 않았습니다.

Cursor는 `~/.agents/skills`와 `~/.claude/skills`, GitHub Copilot은 `~/.agents/skills`, Devin은 `~/.agents/skills`와 `~/.copilot/skills`도 읽으므로, 여러 클라이언트를 켜면 같은 진입점이 중복으로 표시될 수 있습니다.

Grok은 Codex(`~/.agents/skills`)와 Claude Code(`~/.claude/skills`)의 탐색 경로도 읽으며, 같은 이름의 스킬은 `~/.grok/skills`, `~/.agents/skills`, `~/.claude/skills` 순으로 우선합니다. Codex 진입점은 `agents/openai.yaml`로 자동 선택을 막으므로, Grok에서는 "명령 후보만" 스킬도 자동으로 선택됩니다. Grok을 사용한다면 동기화 대상으로 Grok을 선택하세요.

모드는 각 스킬의 상세 페이지나 목록의 "사용 방식"에서 선택하세요. 목록에서는 현재 모드를 확인하고 그 자리에서 전환할 수 있습니다. MCP는 비공개 스킬의 내용을 반환하지 않으며, 동기화에 성공한 뒤에는 해당 스킬의 명령 후보 진입점도 제거합니다.

목록에서 저장이 진행되는 동안 브라우저의 뒤로 가기를 누르거나 새로 고침하면, Skilvella는 저장 결과를 확인한 뒤 최신 설정을 표시합니다. 연결이 끊겨 수락되지 않은 요청은 취소되며, 확인 결과가 화면에 표시됩니다.

| 모드 | 자동 선택을 위해 전달되는 이름과 설명 | 명령 후보 |
| --- | --- | --- |
| 검색만(기본값) | 전달하지 않음 | 표시하지 않음 |
| 명령 후보만 | 전달하지 않음 | 표시함 |
| 자동 선택 + 명령 후보 | 전달함 | 표시함 |

명령 후보를 표시하는 스킬은 동기화 대상별 호출 명령(Codex는 `$name`, 다른 클라이언트는 `/name`)이 목록의 스킬 이름 아래와 상세 페이지의 "사용 방식"에 표시됩니다. 이름에 소문자, 숫자, `-` 이외의 문자가 포함되면 `skill-<ID의 처음 8자>`가 되고, 같은 이름의 공개 스킬이 있으면 `<name>-<ID의 처음 8자>`가 되므로 표시된 명령을 사용하세요. 명령이 없을 때는 상세 페이지에 이유(검색만, 동기화 대상 미선택, 비공개, 읽기 오류)가 표시됩니다. 목록에서 비공개에서 공개로 전환한 스킬의 명령은 새로 고침 후에 나타납니다.

목록에서 스킬을 체크하고 일괄 작업의 "사용 방식"을 선택한 뒤 "선택 항목에 적용"을 누르면 여러 스킬의 모드를 한꺼번에 바꿀 수 있습니다. "변경 안 함"은 현재 모드를 유지합니다. 공개 상태와 태그를 동시에 변경할 수도 있습니다.

"모든 스킬" 아래의 "원본별 일괄 설정"을 열면 여러 출처를 선택하여 "선택한 출처에 적용"으로 공개 상태와 사용 방식을 함께 바꿀 수 있습니다. 대상 범위는 실행 시점에 등록된 모든 페이지의 스킬이며, 이후 추가된 스킬에는 적용되지 않습니다. 사전 확인 개수는 스캔 색인을 기준으로 하며 누락·오류 항목은 제외됩니다. 결과에는 업데이트된 개수와 제외된 개수가 표시됩니다. 공개할 때는 파일을 다시 확인하며, 누락·읽기 불가·형식 오류 등으로 재검증할 수 없으면 모든 항목의 설정 저장이 취소됩니다. 설정은 단일 트랜잭션으로 저장되며 원본 스킬은 변경되지 않습니다.

Codex에는 "자동 선택은 켜되 후보에는 표시하지 않음"이라는 별도 설정이 없으므로, Skilvella는 그에 해당하는 세 가지 모드를 제공합니다. 자동 선택일 때도 원본 내용의 전체 사본을 항상 보관하지는 않으며, 필요할 때 MCP에서 내용을 가져옵니다. 후보에 표시되지 않는 스킬은 명시적 호출 전용인 `$skilvella-search`로 검색할 수 있습니다. MCP의 `search_skills`를 직접 사용할 수도 있습니다.

사용 방식 모드는 모든 동기화 대상에 공통입니다. 진입점 위치는 위 표와 같습니다. 스킬을 비공개로 하거나 모드를 바꾸면 더 이상 필요 없는 산출물은 탐색 경로 밖(`~/.agents`, `~/.claude`, `~/.grok`, `~/.cursor`, `~/.copilot`, `<Devin 설정>` 바로 아래의 `skilvella-staging` / `skilvella-retired`)으로 옮겨집니다. 알 수 없는 파일이나 수동 편집이 감지되면 덮어쓰지 않으며 설정 페이지에 동기화 오류가 표시됩니다. 디스크 공간 부족이나 강제 종료로 불완전한 임시 파일이 남으면 기존의 정상 색인을 보호하면서 중단됩니다. 표시된 경로의 내용을 확인한 뒤 다시 시도하세요. 연동을 끄면 해당 연동이 소유한 진입점이 탐색 경로에서 제거됩니다. 동기화가 중지된 동안에는 이전의 후보와 자동 선택 설정이 남아 있을 수 있습니다. 원본 파일, 공개 상태, 편집 이력은 바뀌지 않습니다. Codex의 후보 표시가 갱신되지 않으면 후보 메뉴를 다시 열거나 Codex를 다시 시작하세요. Claude Code는 실행 중인 세션에서도 `~/.claude/skills`의 변경을 반영하지만, 세션을 시작한 뒤에 `~/.claude/skills` 자체를 만들었다면 `/reload-skills`를 실행하세요. 이미 기존 대화에 로드된 내용은 제거할 수 없습니다.

## 표시 설정

라이브러리에서 왼쪽의 폴더를 선택하고 "표시 이름 변경"을 열면 화면에 표시되는 폴더 이름을 바꿀 수 있습니다. 입력은 앞뒤 공백을 포함해 100자 이내여야 하며 줄바꿈 같은 제어 문자는 사용할 수 없습니다. 앞뒤 공백은 저장할 때 제거되고, 비워 두면 원래 식별자로 돌아갑니다. 표시 이름은 앱 안에 저장되며, 실제 폴더 이름, 스킬 ID, 공개 설정, 편집 이력은 바뀌지 않습니다. 표시 이름이 중복되어도 되지만, 변경한 이름에는 원래 식별자가 함께 표시됩니다.

관리 화면의 "설정"에서 언어를 자동 또는 9개 언어(일본어, 영어, 중국어 간체, 중국어 번체, 한국어, 스페인어, 프랑스어, 독일어, 브라질 포르투갈어) 중에서 선택할 수 있습니다. 기본값 "자동(브라우저 언어)"은 브라우저의 언어 설정을 따릅니다. 언어는 선택하면 저장되며, JavaScript가 꺼져 있으면 "저장"을 누르세요. 선택은 같은 브라우저에서 연결 포트별로 저장되고, 이미 열려 있는 다른 탭에는 다음에 불러오는 페이지부터 적용됩니다. 이전 버전의 언어 설정은 같은 브라우저에서 같은 주소로 관리 화면을 열 때 승계됩니다. 승계에는 JavaScript가 필요합니다. 스킬 이름, 설명, 본문, 경로, 기술적인 오류 상세는 원문 그대로 유지됩니다. 트레이와 메뉴 막대의 메뉴, `--help` 같은 명령줄 출력, 시작 메시지와 오류, 설치 프로그램(Setup) 버전의 메시지 상자도 같은 9개 언어로 표시됩니다. 이 언어들은 환경 변수 `SKILVELLA_LANGUAGE`(예: `ja`, `pt-BR`) → `LC_ALL` → `LC_MESSAGES` → `LANG` → OS 표시 언어 순으로 결정되며, 결정할 수 없으면 영어가 사용됩니다. MCP 도구의 이름과 설명은 영어입니다.

JavaScript가 켜져 있으면 테마를 자동, 밝게, 어둡게 중에서 선택할 수 있습니다. 선택은 브라우저에 저장되며, 자동은 브라우저의 색 구성표 설정을 따릅니다.

## 데이터와 백업

| OS | 기본 데이터 위치 |
| --- | --- |
| Windows | `%LOCALAPPDATA%\Skilvella` |
| macOS | `~/Library/Application Support/Skilvella` |
| Linux | `$XDG_DATA_HOME/skilvella` 또는 `~/.local/share/skilvella` |

`SKILL.md`와 참조 파일의 원본(source of truth)은 등록된 폴더입니다. 데이터 폴더의 `library.sqlite3`에는 검색 색인 외에도 태그, 카테고리, 공개 설정, 등록 위치, 폴더 표시 이름, 편집 이력이 저장됩니다. **DB 전체를 삭제하면 이 관리 데이터가 사라집니다.**

백업하려면 먼저 Skilvella를 종료한 뒤 데이터 폴더와 등록된 폴더를 모두 복사하세요. DB만으로는 현재 스킬 파일을 복원할 수 없습니다. 다른 PC에서는 등록된 출처의 절대 경로가 다르므로, DB를 그대로 공유하여 동시에 사용하는 것은 지원하지 않습니다.

## 옵션과 문제 해결

```sh
skilvella --data-dir /absolute/path/to/data --port 7465 --no-watch
skilvella --help
```

- 포트가 사용 중이면 기존 프로세스를 종료하거나 `--port`로 변경하세요. 관리 화면과 MCP는 같은 포트를 사용합니다.
- 이전 Windows 버전에서 업데이트한 뒤 관리 화면이 돌아오지 않으면, 일반 구성에서는 업데이트된 `skilvella.exe`를, Toolport 관리 하에서는 런처를 한 번 실행하세요.
- 이전 버전에서 중단된 폴더 이동을 시작할 때 복구할 수 없으면 시작이 중단됩니다. 원본 데이터와 이전 기록은 유지됩니다.
- 데이터 위치와 스킬 등록 위치는 서로 겹칠 수 없습니다. 로컬 디스크의 서로 다른 폴더를 지정하세요.
- 다른 탭에서 한 편집도 저장할 때 충돌로 감지됩니다. 남아 있는 초안을 복사하고 새로 고침한 뒤 최신 내용에 병합하세요.
- 검색은 공백으로 구분한 AND와 부분 문자열 일치를 사용합니다. 일본어 질의로 영어 스킬을 의미 기반으로 검색하는 기능, 임베딩 모델, 클라우드 동기화는 포함되어 있지 않습니다.
- 원본 폴더가 오프라인이 되어도 등록 데이터와 이력은 유지됩니다. 다시 연결된 후 다시 스캔하세요.

연결은 `127.0.0.1`로 제한됩니다. 같은 PC의 사용자와 프로세스를 신뢰할 수 있는 환경에서 사용하도록 만들어졌습니다.
